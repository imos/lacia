# 全体の構成

`lacia` は、Codex や Claude Code を、秘書の「レイシア」として動かすための道具です。会話で受け付けた依頼について、進み具合や成果、オーナーさんに確かめてほしいことを記録します。

## 実行ファイル、記録のリポジトリー、会話

- `lacia` の実行ファイルは、このリポジトリーからビルドします。Web の画面、タスクの読み書き、依頼の受付、予約、Git への保存と、これらを操作するコマンドが入っています。
- 記録のリポジトリーは、オーナーさんごとに用意します。タスク、記憶、予約の定義、各自の決まりをここに保存します。
- Codex か Claude Code の会話は、依頼にどう応じるかを判断し、調査や作業をして返事を書きます。サーバーからも、オーナーさんの手元からも起動できます。

オーナーさんは、レイシアが仕える人です。1つの記録のリポジトリーにつき1人です。レイシアは、環境変数 `LACIA_USER`、記録の `.lacia/config.json` の `user` の順に、その方の呼び名を探します。どちらもなければ「オーナーさん」と呼びます。

コードと記録は、別のリポジトリーに分けています。コードには、特定の人の名前、アドレス、予定を入れません。記録の側には、共通の決まりの写しを置きません。こうしておくと、実行ファイルを新しくしても記録と衝突せず、記録を人に見せずにコードだけを配れます。

## 1つの実行ファイルと、その役割

`lacia` は、Go で書いた1つの実行ファイルです。最初の引数で、役割が変わります。

| 使い方 | 役割 |
| --- | --- |
| `lacia serve` | サーバーです。Web の画面、タスクの読み書き、依頼の受付、会話とのやり取り、予約、Git への保存を受け持ちます |
| `lacia task`、`lacia ask` など | タスクの操作と、依頼の送信をするコマンドです。会話も、人も、同じコマンドを使います |
| `lacia rules`、`lacia init`、`lacia codex`、`lacia claude` | 決まりの表示、記録の初期設定、会話の起動です |
| `lacia agent` | 端末でサーバーから通知用の情報を読みます。登録済みの端末では、予約や申し送りも受け取ります。macOS の通知アプリは、このコマンドを起動して使います |

1つの実行ファイルを配れば、サーバーとタスクを操作するコマンドがそろいます。同じ版を使う限り、サーバーとコマンドは同じ形式のタスクを読み書きし、その版に合った決まりを表示できます。

## サーバーが行うことと、会話が行うこと

手順の決まった操作は、会話を通さずに、サーバーがその場で行います。会話には、判断と文章が要る仕事だけを渡します。

| サーバーが行うこと | 会話が行うこと |
| --- | --- |
| 状態の変更と、履歴への追記 | どのタスクの話かを決めること |
| タスクの ID の採番 | 調査、実作業、検証 |
| 依頼の受付と、順番の管理 | `task.md` などの文章を書くこと |
| 予約の時刻を見て、依頼にすること | オーナーさんへの返事 |
| Git へのコミットとプッシュ | サブエージェントへ仕事を任せること |
| Google Calendar から予定を読むこと | |
| `TODO.md` を作ること | |

たとえば Web のボタンでタスクの状態を変えると、サーバーがその場でファイルを書き換え、画面に結果を表示します。会話の応答や Git への保存を待たずに済みます。

サーバーは起動時にすべてのタスクの `task.md` を読み、メモリーに索引を作ります。サーバー自身が書き換えたときに索引を更新し、定期的にもファイルを読み直します（既定は10秒ごと）。会話がファイルを直接編集した場合も、次に読み直したときに画面へ反映されます。

## サーバーと会話の関係

依頼を受ける会話は、1つのサーバーにつき1本です。これを「窓口」と呼びます。窓口が依頼を順に受け取るのは、同じタスクを複数の会話が同時に書き換えるのを防ぐためです。実作業は、窓口がサブエージェントへ任せます。

```
オーナーさん ──(Web、Discord、lacia ask)──▶ サーバー ──(依頼を1件ずつ)──▶ 窓口の会話 ──▶ サブエージェント
                                          ▲                              │
                                          └──(lacia task ...、ファイルの編集)──┘
```

- サーバーは、依頼を待ち行列に入れて、1件ずつ窓口へ渡します。詳しくは[依頼の受付](requests.md)にあります。
- 会話は、`lacia` コマンドでタスクを操作します。サーバーは、自分のアドレスを環境変数 `LACIA_API` で会話へ渡すので、会話がコマンドで頼んだ更新は、このサーバーが処理します。
- サーバーが使う記録を直接書ける会話は、文章の部分（`task.md` の本文、`notes.md`、成果物）も編集できます。読み取り専用のコピーで動く会話では、`lacia task write` や `lacia task attach` でサーバーへ送ります。
- 会話は、記録のリポジトリーをコミットしません。コミットとプッシュは、サーバーがまとめて行います。

サーバーを使わずに、オーナーさんが `lacia codex` や `lacia claude` で会話を手で起動することもできます。このときも、会話は同じ決まりと同じコマンドを使います。コマンドは、接続先の指定か、同じ記録にサーバーが残したアドレスを使えます。サーバーを指定しない構成では、書き込める記録をコマンドが直接扱います。 [接続先の見つけ方](records.md#手元のサーバーをコマンドが見つける)

## 決まりの置き場所

会話が従う決まりは、実行ファイルに埋め込んであります。記録のリポジトリーには、各自の決まりだけを置きます。コマンドの使い方を説明する決まりと、そのコマンドを実行するプログラムを同じ版で配るためです。詳しくは[決まりと会話の起動](rules.md)にあります。

## プロファイル

1つの設定ファイルに複数のサーバーの設定をまとめられます。サーバー1つ分の設定が「プロファイル」です。たとえば、仕事用と家庭用の2つのプロファイルを持ち、別々の記録のリポジトリーを受け持たせる使い方があります。

- 1つのプロセスが動かすのは、1つのプロファイルです。
- プロファイルの名前に、コードは意味を持たせていません。何をするかは、設定の組み合わせで決まります。
- プロファイルどうしは、決まった入口だけで、伝言と引き継ぎをやり取りします。互いのリポジトリーは読みません。

プロファイルが1つだけなら、設定ファイルも、プロファイルの指定も要りません。詳しくは[複数のプロファイル](profiles.md)にあります。

## 手元の形と、離れた場所で動かす形

ここでいう「サーバー」は `lacia serve` のプロセスです。ローカル環境で起動しても、別の環境で起動しても、記録と Web の画面を受け持ちます。

| | ローカル環境で使う | 別の環境でサーバーを動かす |
| --- | --- | --- |
| 記録 | ローカル環境に書き込める記録を置き、同じ環境で `lacia serve` を起動します | サーバーの環境に書き込める記録を置きます。手元の端末で記録のファイルも読む場合は、読み取り専用のコピーを置けます |
| Web とコマンド | 同じ環境の `127.0.0.1:10148` へつなぎます。依頼を受けるサーバーの宛先は、同じ記録のコマンドが見つけられます | サーバーの URL か許可された転送を使います。手元の端末からコマンドで更新するときも、そのサーバーへ送ります |
| 会話と予約 | 通常はローカル環境のサーバーが会話を起動し、予約の `to` を省けます | 通常はサーバーが会話を起動します。別の端末で動かす仕事があれば、その端末を登録して宛先を選びます |
| macOS の通知 | 使うときは、通知アプリを同じ環境のサーバーにつなぎます | 使うときは、通知アプリを別の環境のサーバーにつなぎます。記録のコピーを最新に保つ設定もできます |

どちらでも、依頼と予約を動かすには `--state` と `--codex` か `--claude` が要ります。Git の自動保存、Google Calendar、Discord は、使う機能に合わせて設定します。Kubernetes や複数のプロファイルは、その構成を使うときに設定します。 [ローカル環境で始める](../../README.md#ローカル環境で始める) · [Mac の通知](notifications.md) · [設定の一覧](settings.md)

## コードの場所

| 場所 | 中身 |
| --- | --- |
| `cmd/lacia/` | コマンドの受付、サーバーの起動と各機能の初期設定 |
| `internal/task/` | タスクの読み書き、ID の採番、文章の点検 |
| `internal/web/` | Web の画面と API |
| `internal/request/`、`internal/codex/`、`internal/claudecode/` | 依頼の待ち行列と、Codex や Claude Code とのやり取り |
| `internal/schedule/` | 予約 |
| `internal/rules/` | 実行ファイルに埋め込む決まり |
| `internal/self/` | 自分についての記録 |
| `internal/calendar/`、`internal/gcal/` | 予定の表示と、Google Calendar からの取得 |
| `internal/gitsync/`、`internal/todo/` | Git への保存と、`TODO.md` の作成 |
| `internal/discord/`、`internal/daylog/` | Discord とのやり取りと、日ごとのログ |
| `internal/wait/`、`internal/agent/`、`internal/notify/` | 終了を待つ仕事、端末で動く `lacia agent` と通知の処理 |
| `internal/caller/` | コマンドを呼んだ会話の見分け |
| `internal/login/`、`cmd/lacia/shims/` | ログインの違う Codex の呼び分けと、実行ファイルに埋め込んだコマンド |
| `macos/notifier/` | Mac のメニューバーのアプリ |
