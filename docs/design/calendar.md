# 予定の連携

サーバーは、Google Calendar から予定を直接読んで、ホームの画面に出します。Mac の通知アプリも、その予定をもとに会議の開始を知らせます。この文書では、連携の仕方、読むカレンダーの決め方、祝日、表示の上書きを説明します。

サーバーが行うのは、読み取りだけです。予定を作ったり変えたりする処理は、サーバーにはありません。

## 始め方

ローカル環境で使う場合は、次の2つで連携できます。

1. 記録のリポジトリーで `lacia init` を実行して、予定を読む Google のアカウントを入力します。`.lacia/calendars.json` が書かれます。
2. `--state` を付けて `lacia serve` を起動し、Web の「予定の連携」のページ（`/settings/calendar`）で、予定を読むことを Google アカウントごとに許可します。

`--state` が要るのは、許可の情報をそこへ保存するためです。別の環境でサーバーを動かす場合も、カレンダーの一覧と許可の情報を持つのは、そのサーバーです。手元からは、実際にブラウザーで開けるサーバーのアドレスで「予定の連携」を開きます。公開のアドレスを使う場合は、そのアドレスを `site` に指定し、対応する OAuth クライアントを用意します。 [OAuth のクライアント](#oauth-のクライアント)

## 読むカレンダー（`calendars`）

表示して読むカレンダーは、JSON の一覧で決めます。

```json
[
  {"account": "tanaka@example.com", "calendar_id": "primary", "label": "会社", "color": "#1a73e8"},
  {"account": "tanaka@example.com", "calendar_id": "family@group.calendar.google.com", "label": "家族"}
]
```

| 項目 | 必須 | 中身 |
| --- | --- | --- |
| `account` | ○ | 許可を出す Google のアカウントです |
| `calendar_id` | ○ | カレンダーの ID です。そのアカウント自身のカレンダーは `primary` です |
| `label` | ○ | 画面に出す名前です |
| `color` | | 画面に出す色です |
| `require_verified` | | `true` にすると、取得した側が対象を確かめた印のないカレンダーを、表示しません |

一覧は、次の順で探します。

1. 設定の `calendars` に指定したファイル
2. 記録のリポジトリーの `.lacia/calendars.json`

どちらもなければ、どのカレンダーも表示せず、読みません。実行ファイルは、カレンダーの既定を持っていません。同じカレンダーを2回書くと、起動のときにエラーになります。

Mac の会議の知らせの対象は、ローカル環境で動くサーバーにつないでいても、別の環境のサーバーにつないでいても、接続先の一覧です。`lacia agent` は、サーバーの `GET /api/calendar/scope` から一覧を受け取ります。

共有カレンダーは、読み取りを許可するアカウントでGoogle Calendarを開き、該当するカレンダーの「設定と共有」に進んでください。「カレンダーの統合」に出るカレンダーIDを `calendar_id` に書きます。相手には予定の詳細を読める権限が必要です。本人のカレンダーには `primary` を指定できます。 [カレンダーIDの確認手順](https://support.google.com/calendar/answer/44105?hl=ja)

## OAuth のクライアント

Google の許可を求めるには、OAuth のクライアントが要ります。次の順で決まります。

| 条件 | 使うクライアント |
| --- | --- |
| 設定に `google-client` がある | そのファイルのクライアント |
| 設定に `google-client` がない | 「予定の連携」のページで、ご自身のクライアント ID とシークレットを入力します |

- 手元の環境では、Google Cloud で「デスクトップ アプリ」のクライアントを作ります。連携は PKCE と、手元のアドレスへ戻る仕組みを使います。
- `google-client` には、Google Cloud の「認証情報」からダウンロードした JSON を指定します。組織の中だけで使うクライアントへ置き換えるときなどに使います。種類が「ウェブ アプリケーション」のクライアントも使えます。
- 公開URLのサーバーではウェブアプリケーション用のクライアントを使い、実際のスキーム、ホスト、パスと一致する戻り先をGoogle Cloudへ登録してください。手元のMacではデスクトップアプリ用のクライアントとループバックを使います。 [Webサーバー用のOAuth](https://developers.google.com/identity/protocols/oauth2/web-server) · [デスクトップ用のOAuth](https://developers.google.com/identity/protocols/oauth2/native-app)
- 許可のあとに Google から戻る先は、`site` があれば `<site>/oauth/google/callback`、なければ `http://127.0.0.1:<ポート>/oauth/google/callback` です。

## 許可を出す

「予定の連携」のページに、一覧のアカウントが並びます。アカウントごとに「Googleで許可する」を押して、Google の画面で許可を出します。

- 求める許可は、予定の読み取り（`calendar.readonly`）だけです。設定で `calendar-write = true` にすると、予定の作成と変更（`calendar.events`）の許可も求めます。その場合も、サーバーが自分から予定を書き換えることはありません。
- 許可を出したアカウントが、ページで選んだアカウントと違うときは、保存しません。別のアカウントでログインしたまま許可した場合に、取り違えないためです。
- 許可の情報は、`--state` のディレクトリーの `secrets/gcal.json` に保存します。記録のリポジトリーにも、画面にも出しません。
- 一覧のカレンダーの持ち主が連携していなくても、そのカレンダーを共有されている別のアカウントが連携していれば、そちらを通して読みます。

## 取得

サーバーは10分ごとに、きょうを含む7日間の予定を読みます。アカウントを連携したときと外したときは、すぐに読み直します。

- `--state` を指定したサーバーは、取得した予定を `<state>/calendar/snapshot.json` に保存します。Web の画面と `lacia agent` は同じデータを使います。端末の `lacia agent` は `GET /api/calendar/snapshot` で受け取ります。
- 直接取得では、許可したアカウント、設定のカレンダーID、予定を読める権限と、一覧の最後のページまでを確かめます。途中のページが空でも次のページがあれば読み続けます。最後まで取得できたら、0件でも現在の予定へ入れ替えます。 [Google Calendarの予定一覧API](https://developers.google.com/workspace/calendar/api/v3/reference/events/list)
- 取得の途中で通信に失敗した場合は、そのカレンダーだけ前回の予定を残します。Webの「取得の詳細」には、最後に成功した時刻と今回の試行時刻を別に出します。日時やカレンダーの権限が確かめられない場合も、成功した0件と区別します。
- 詳細を読む権限が失われたとGoogleから分かった場合や、連携を外してほかに読めるアカウントがない場合は、そのカレンダーの予定の詳細を表示と会議通知の対象から外します。カレンダーの読み手はアカウントとカレンダーIDの組み合わせで決めます。
- 保存前にJSONを点検し、状態ディレクトリーの一時ファイルを書き終えてから保存先と入れ替えます。再起動後も同じファイルを読みます。対象期間は取得したタイムゾーンの開始日を含み、終了日の始まりで終わります。

- 予定の説明文、参加者、会議のアドレスは、会議かどうかを判定するためだけに使い、保存しません。
- 取り消された予定と、勤務場所の予定は、スナップショットに入れません。

### 以前の定期タスクから切り替えるとき

以前の定期タスクが予定ファイルを作っている場合は、設定の `calendar` で指定した場所か従来の置き場所から読みます。その経路では、前回4件以上のカレンダーで件数が半分未満になると、前回分を残して一部だけ取得できたことを示します。Gitへ保存する旧ファイルにも同じ判定を使います。

本体がすべての設定済みカレンダーを直接取得できる状態になると、以前の定期タスクと旧ファイルの取り込みを見送ります。全カレンダーを読み終えた最初のスナップショットは、直接取得がこの保存先を受け持つ印を持ちます。この印は再起動後も読み、あるカレンダーの権限やOAuthの接続が失われても、古い定期タスクのファイルを自動で取り込みません。権限を外したところに以前の予定が戻るのを防ぐためです。

運用上、以前の定期タスクへ戻す必要がある場合は、その経路で予定を読んでよいことを確認し、サーバー側の設定に `calendar-direct = false` を指定します。そのうえで旧ファイルが新しく書かれ、WebとMac側の通知計画が更新されたことを確かめます。直接取得に戻すときは設定を外し、対象の連携と初回の取得を確かめます。

## 会話から予定を読む

`lacia calendar list` は、接続先のレイシアが保存した予定から、きょうの分を表示します。`--period tomorrow` であしたの予定を、`--period week` できょうから7日間の予定を読めます。日付で指定するときは `lacia calendar list --from 2026-11-27 --until 2026-11-29` のように書きます。終了日その日は含まず、期間は最大7日です。

予定を読む範囲と表示対象はWebのカレンダー設定を使い、非公開に指定された予定は時刻と「非公開の予定」という題名だけを返します。`--json` では、カレンダーごとの対象期間、取得に成功した時刻、最後の試行時刻、結果が古いかどうかも確認できます。0件でも、一部失敗や未取得の区間があれば表示に出ます。今起きた取り消しや変更を答えるときは、元の Google Calendar で確かめます。

Macの会議通知は引き続き通知用のスナップショットを使います。範囲内の取得がすべて成功し、該当する会議が一覧にない場合は通知予定を取り下げます。一時的な失敗や取得した期間の外にある会議では、以前の通知予定を保ちます。対象から外したカレンダーや、権限を失ったと確かめられたカレンダーの通知を取り下げます。


## 表示

- 日付と曜日は、記録の `timezone`（既定は `Asia/Tokyo`）で判定します。
- 週の予定の日付は、土曜日を青、日曜日と祝日を赤にします。祝日には印を付けて、祝日の名前を読めるようにします。
- 日本の祝日を表示しない導入先では、`serve.conf` に `calendar-holidays = off` を指定します。省略時は `jp` です。土日表示は祝日の設定にかかわらず使えます。
- 祝日のデータは、内閣府が公開している「国民の祝日」の CSV を、実行ファイルに入れています（`internal/calendar/holidays.csv`）。いまは、1955年から2027年までが入っています。それより先の祝日は、推定しません。
- 新しい年のデータが公開されたら、`python3 scripts/update-holidays.py` で取り直して、差分とテストを確かめます。祝日表示を使う導入先では、同梱データの最終年に入ると `lacia doctor` が収録範囲を知らせます。サーバーの設定ファイルを使っている場合は `--config` と必要に応じて `--profile` を指定します。 [内閣府の祝日データ](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)

### 表示の上書き（`calendar-overrides`）

終日の予定に、オーナーさんが確かめた内容を重ねて表示できます。設定の `calendar-overrides` のファイルに、予定の ID ごとに書きます。ファイルがなければ、上書きはしません。

```json
{
  "events": [
    {
      "id": "（予定の ID）",
      "display_basis": "user_confirmed_day",
      "display_markers": [
        {"time": "09:30", "title": "集合", "basis": "lacia_interpretation"}
      ]
    }
  ]
}
```

- `display_basis` に書けるのは `user_confirmed_day` だけで、終日の予定にだけ使えます。
- `display_markers` は、その日の中の目安の時刻です。`time` は `HH:MM` の形で書き、`basis` には `lacia_interpretation` と書きます。レイシアの解釈であることが、画面で分かるように出ます。
- `display_basis` のある予定は、会議の知らせの対象から外れます。

既定の場所は `.lacia/calendar-overrides.json` です。設定の `calendar-overrides` で変えられます。

### 決まった題名の予定を出さない規則

題名で予定を表示から外す規則は、記録の設定の `calendar_hidden` に書きます（[記録のリポジトリー](records.md#記録の設定laciaconfigjson)）。実行ファイルには、規則は入っていません。

```json
"calendar_hidden": {
  "always": ["^lunch break$"],
  "week": ["^ooo(?:$|[^\\p{L}\\p{N}_])"]
}
```

- `always` に当たる予定は、ホームの予定欄のどの一覧にも出しません。Mac の会議通知も止めたいときは、通知アプリの `exclude_meetings` に除外の規則を書きます。[会議通知の除外](notifications.md#除外exclude_meetings)
- `week` に当たる予定は、7日間の一覧からだけ外します。
- どちらも正規表現で、題名を整えたものと照らします。整えるときは、英字を小文字に、全角の英数字と記号を半角にして、続いた空白を1つにします。
- 読めない正規表現があると、サーバーは起動しません。


## 記録の時間帯との対応

取得する日付の範囲とGoogle Calendar APIへ渡す時間帯は、記録の `timezone` を使います。新しく取得したスナップショットの `timezone` にも同じIANAの名前を書きます。以前の `Asia/Tokyo` のスナップショットは、そのまま読めます。

画面は、記録で選んだ時間帯へ時刻を直して並べます。終日の予定は、日付を保ちます。夏時間の日にも、午前9時の予定は画面の9時の位置に置きます。最終取得が新しいかを判断する朝6時の境界も、その土地の時計で決めます。会議の通知の時刻は、通知側で記録の設定を取得できればその時間帯、取得できないときは保存済みデータの時間帯で書きます。
