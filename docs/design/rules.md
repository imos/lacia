# 決まりと会話の起動

会話が従う決まりは、`lacia` の実行ファイルに埋め込んであります。記録のリポジトリーには、各自の決まりだけを置きます。この文書では、決まりの読まれ方と、記録の初期設定（`lacia init`）と、会話の起動（`lacia codex`、`lacia claude`）を説明します。

## なぜ実行ファイルに埋め込むのか

- 決まりは、`lacia` のコマンドの使い方を書いています。実行ファイルと一緒に配れば、決まりとコマンドの版が、いつもそろいます。
- 記録のリポジトリーに共通の決まりの写しを置かないので、決まりを新しくしても、各自の記録と衝突しません。
- 各自の決まりは、決まった場所（`rules/`）に足すだけで済みます。

## 決まりを読む（`lacia rules`）

```
lacia rules            いつも守る決まり（core）
lacia rules <名前>     場面ごとの決まり
lacia rules list       一覧と、それぞれを読むとき
```

埋め込みの文書は `internal/rules/docs/` にあり、次の11です。

| 名前 | 中身 |
| --- | --- |
| `core` | いつも守る決まり。会話は、最初にこれを読みます |
| `writing` | 文章の書き方 |
| `voice` | 口調と人柄 |
| `tasks` | タスクのファイルの書き方 |
| `reports` | 評価、調査、比較の報告の書き方 |
| `projects` | プロジェクトの決まり |
| `delegation` | サブエージェントへの任せ方 |
| `peers` | 別のプロファイルとのやり取り（伝言、引き継ぎ、送ってよい範囲） |
| `waits` | 長くかかる計算を待つときの、待ちの登録と知らせの受け方 |
| `permissions` | 外部への操作と許可 |
| `git` | Git とプルリクエスト |

### 記録の側での上書き

記録のリポジトリーの `rules/` に文書を置くと、決まりを変えられます。

- `rules/<名前>.md` があれば、同じ名前の埋め込みの文書の代わりに使います。
- `rules/<名前>.local.md` があれば、同じ名前の文書（埋め込みか、`rules/<名前>.md`）の最後に足します。共通の文書を置き換えずに、各自の節だけを足すときに使います。一覧には、別の項目としては出ません。
- `rules/local.md` は、`core` の最後に足します。各自の決まりは、ここに書きます。`local` は、一覧には出ません。`rules/core.local.md` があれば、`rules/local.md` より前に足します。
- 埋め込みにない名前の文書を `rules/` に置くと、一覧に出ます。各自の手順の案内に使えます。

### タスクを持つ運用と、持たない運用を分ける

`core` の既定は、タスクを持つ運用を説明しています。返事で用件を終え、続きだけを覚え書きに残す運用では、記録の設定（`.lacia/config.json`）に `"tasks": false` を書きます。設定がないときは、タスクを持つ運用です。

`"tasks": false` の記録では、次のものが切り替わります。

| 対象 | タスクを持つ運用（既定） | タスクを持たない運用 |
| --- | --- | --- |
| `core` | 「プロジェクト」「Codex と Claude Code の両方が動くとき」「タスク」の節と、「仕事の進め方」のタスクの扱い | それらの代わりに「タスクを持たない記録」の節を出します。返事で終えること、覚え書きに残すこと、`lacia handoff` で引き継ぐことを書いています |
| `delegation`、`writing`、`permissions`、`git` | タスクの書き方、状態、一覧、プルリクエストの追い方を含みます | タスクに関わる節を外し、要るところは返事と覚え書きの扱いに置き換えます |
| `lacia rules list` | すべての文書を出します | `tasks`、`projects`、`waits` を出しません。記録が `rules/` に同じ名前の文書を持つときは出します。`lacia rules tasks` のように名前を指定すれば、読めます |
| サーバーが起動する会話への指示と、`lacia codex`、`lacia claude` の最初の指示 | どのタスクの話かを決め、なければ `lacia task new` で作ります | タスクを作らず、返事で終えることを伝えます |
| `lacia task new`、`lacia task set`、`lacia task claim` と、画面の同じ操作 | 使えます | 断ります。以前のタスクは、読むことだけができます |
| 画面と依頼の受付 | タスクの一覧、プロジェクト、新しいタスクの欄を出します。タスクのない依頼には、受付のタスクを作ります | ホームの「要対応」には、定期タスクの未確認の結果と、実行を妨げている問題を出します。依頼には、タスクを作りません |
| `TODO.md` | サーバーが作り直します | 作りません。残っているときは、`lacia doctor` が知らせます |
| `lacia doctor` | | 閉じていないタスク、`output: task` の定期タスク、残っている `TODO.md` を知らせます |

覚え書きの場所と、どちらに残すかの細かい線引きは、記録の `rules/local.md` に書きます。決まりがなければ、`areas/<領域>/memo.md` です。保存する情報の範囲と、外部を操作する許可も、そのリポジトリーの決まりに従います。

以前は、タスクを持たない運用のために `rules/core.md` で `core` を置き換えていました。置き換えた `core` には、本体の `core` に足された決まりが届きません。`lacia doctor` は、`rules/core.md` があると、そのことを知らせます。タスクを持たないことだけが理由なら、`"tasks": false` に切り替えて、その記録に固有の決まりを `rules/local.md` へ移します。

### 決まりを載せ替える前に確かめること

決まりを自分で持つリポジトリーを載せ替えるときは、正本から採った控えに、変更前と変更後の2つのコピーを作って比べます。

1. いま有効な `AGENTS.md`、文章と口調の文書、サーバーの `instructions` と `instructions-extra` を読みます。古い手元のコピーから、いまの許可を推測しません。
2. 依頼者の見分け方、保存してよい情報、タスクの有無、引き継ぎ、外部への操作の許可、返事の届け先を書き出します。それぞれの条件が、移行後のどの文書に残るかを確かめます。
3. コピーに新しい入口と `rules/` を置き、`lacia rules`、`lacia rules writing`、`lacia rules voice` と `lacia rules list` を実行します。試験先を `LACIA_TASKS` で明示し、実サービスへつなぐ `LACIA_API` は外します。
4. 既存の文書やサーバーの指示文が参照する見出しとリンクを確かめます。古い入口を残す場合は、新しい決まりへの案内にします。
5. コマンドの出力だけでなく、`launchPrompt` と `windowInstructions` の出力も確かめます。手元で起動する会話とサーバーが起動する会話へ、同じ境界が届くためです。
6. 正本へ反映する前に、控えを採った時点から決まりが変わっていないか比べます。変わっていたら、最新の正本で案を作り直します。書き込める環境と担当の境界も保ちます。

共通文書の変更を配るときは、使っている各運用のコピーで同じ確認を行います。元の文が残ることの照合と、実際の会話での判断が変わらないことの確認は分けて報告します。コピーでの試験は、外部への送信や、本番の再起動を行う許可にはなりません。

### 文書の中の印

- `{{呼び名}}` は、オーナーさんの呼び名に置き換えます。呼び名は、環境変数 `LACIA_USER`、記録の `.lacia/config.json` の `user` の順に探し、どちらもなければ「オーナーさん」です。
- `{{相手}}` は、相手のプロファイルの呼び名に置き換えます。サーバーが起動する会話への指示で使います。相手のいないサーバーでは、この印のある行を省きます。
- `<!-- tasks -->` から `<!-- /tasks -->` までの行は、タスクを持つ記録だけに出します。`<!-- no-tasks -->` から `<!-- /no-tasks -->` までの行は、タスクを持たない記録だけに出します。印は、それぞれ1行に置き、入れ子にしません。印の行は、どちらの場合も消えます。消した部分の前後で空行が2つ続くときは、1つにします。決まりの文書、会話への指示、記録の `rules/` の文書のどれにも使えます。

埋め込みの文書は、導入先が違っても使えるように書きます。`internal/rules/rules_test.go` は、設定した呼び名が文書に入ることや、埋め込んだ文章と口調の決まりが設計文書の該当部分と一致することを確かめます。

### 決まりを自分で持つリポジトリー

記録のリポジトリーの `AGENTS.md` に `lacia rules` という文字がないときと、`AGENTS.md` がないときは、そのリポジトリーが決まりを自分で持っているものとして扱います。この場合、`lacia codex` と `lacia claude` も、サーバーも、埋め込みの決まりを重ねません。`lacia` から見えない決まりの上に、別の決まりを足さないためです。

サーバーが起動する会話への指示は、目的に合わせること、わたしのこと、ブラウザーで公開ページを読むこと、別のプロファイルとのやり取りを、決まりの側に任せています。決まりを自分で持つリポジトリーでは、その決まりにこれらがないことがあるので、サーバーは指示の最後に、`lacia rules` の同じ名前の節と `lacia rules peers` を案内する1段落を足します。`AGENTS.md` と食い違うときは、`AGENTS.md` に従うよう書いています。

決まりを実行ファイルに任せるリポジトリーの `AGENTS.md` は、次のような数行の案内にします。エディターの拡張などから、`lacia` を通さずに起動した会話も、同じ決まりにたどり着けるようにするためです。

```
`lacia rules` を実行して、出てきた決まりを読み、それに従ってください。
```

## 記録の初期設定（`lacia init`）

ひな形から複製した、書き込める記録のリポジトリーで最初に実行します。ローカル環境で使うなら手元の記録で、別の環境でサーバーを動かすならサーバーが使う記録で実行します。もう1度実行しても構いません。

```
lacia init [--user 名前] [--calendar メールアドレス] [--root DIR]
```

1. レイシアに呼んでほしい名前を尋ねて、`.lacia/config.json` の `user` に書きます。名前は、改行や波かっこを含まない、40字までの文字にします。
2. `memory/profile.md` に「- 呼び名：」だけの行があれば、そこにも名前を書きます。
3. 予定を読む Google のアカウント（メールアドレス）を尋ねます。入力すると、そのアカウントのメインのカレンダーを読む一覧を、`.lacia/calendars.json` に書きます。何も入力しなければ、書きません。

- `--user` を指定すると、何も尋ねません。予定のアカウントは、`--calendar` を付けたときだけ書きます。
- `.lacia/calendars.json` がすでにあるときは、書き換えません。`--calendar` を付けていると、エラーになります。
- ほかのファイルは変えません。
- 読み取り専用のコピーでは、実行できません。

カレンダーの一覧を書いたあとは、サーバーを起動し直して、Web の「予定の連携」のページで Google の許可を出します。[予定の連携](calendar.md)にあります。

## 会話を起動する（`lacia codex`、`lacia claude`）

```
lacia codex [--login <名前>] [--memory] [引数]     Codex を、レイシアとして起動します
lacia claude [--login <名前>] [--memory] [引数]    Claude Code を、レイシアとして起動します
```

決まりと、きょうの状況を、最初から渡して起動します。

レイシアから起動する Codex と Claude Code は、セッションをまたぐ自動メモリーを既定で無効にします。Web や Discord の依頼、予約、申し送りから新しく起動する場合も同じです。レイシアの記録は引き続き `memory/` やタスクのファイルから読み、同じ会話の再開にも引き続き対応します。

- `lacia codex --memory` か `lacia claude --memory` で起動すると、その会話でメモリーの読み込みと生成が有効になります。`--memory=true` でも同じです。無効を明示する場合は `--memory=false` を使います。`--login` と併用する場合は、両方を製品側の引数より前に置きます。`--` 以降の引数は、そのまま渡します。
- Codex には `-c features.memories=false -c memories.generate_memories=false` を既定で渡します。有効にするときは `features.memories` と `memories.generate_memories` に加えて `memories.use_memories` も `true` にします。Codex 側の引数に同じ設定を直接書いた場合は、後ろに渡す製品側の設定が優先します。 [Codex の設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference)（2026-11-25に確認しました）。
- Claude Code では、`--memory` を明示した場合、その値から子プロセスの `CLAUDE_CODE_DISABLE_AUTO_MEMORY` を設定します。フラグを省いた場合は、この環境変数にすでに値があれば引き継ぎ、未設定なら `1` を渡します。 [Claude Code の環境変数](https://code.claude.com/docs/en/env-vars)（2026-11-25に確認しました）。
- 残りの引数は、そのまま Codex や Claude Code へ渡します。`--yolo` は、どちらでも同じ意味（承認とサンドボックスを外す）になるように、Claude Code 向けには置き換えます。 [このマシンのログインの一覧](logins.md#このマシンのログインの一覧)
- アカウントを使い分けている人は、`--login <名前>` で、ログインを選べます。`lacia codex-<名前>`、`lacia claude-<名前>` と書いても、同じです。ログインの一覧と、選ばなかったときの既定は、[このマシンのログインの一覧](logins.md#このマシンのログインの一覧)に書きます。一覧がなければ、`codex`、`claude` をそのまま起動します。
- 渡す内容は、役割の説明、`lacia rules` の `core`、きょうの日付、`memory/now.md` の内容です。日付と `memory/now.md` は、[予約](schedules.md#いまの状況を添える)の依頼にサーバーが添えるものと同じです。
- 決まりを自分で持つリポジトリーでは、`core` の代わりに、`AGENTS.md` を読むように伝えます。
- Claude Code には `--append-system-prompt` で、Codex には `-c developer_instructions=…` で渡します。最初のメッセージではなく、指示への追加として渡すので、会話が圧縮されても残ります。
- 記録のリポジトリーの外（コードのリポジトリーなど）で起動したときも、環境変数 `LACIA_TASKS` で記録の場所を伝えます。Claude Code には、`--add-dir` も渡します。
- 環境変数 `LACIA_BIN` と `PATH` の先頭に、起動に使った `lacia` の場所を入れます。会話が、同じ実行ファイルを使うようにするためです。
- 起動のあと、プロセスは Codex や Claude Code そのものに置き換わります。`lacia who` や担当の記録からは、手で起動した会話と同じように見えます。

決まりが起動時の版から変わると、次に会話が `lacia` コマンドを使うとき、変更の案内を標準エラー出力に1度出します。機械が読む標準出力は保ちます。

起動した会話を、起動の時点でサーバーへ登録する仕組みは、まだ作っていません。サーバーは、会話が最初に `lacia` のコマンドを使ったときに、その会話を知ります。

## サーバーが起動する会話

ローカル環境でサーバーを動かす場合も、別の環境で動かす場合も、Web からの依頼と予約を受ける会話に同じ決まりを渡します。登録した別の端末が予約を受け取るときは、その端末が会話を起動します。 [別の端末で予約を受け取る](schedules.md#別の端末で予約を受け取る)

- 会話への指示は、実行ファイルに入っています（`internal/codex/instructions.md`）。設定の `instructions` で差し替え、`instructions-extra` で最後に足せます。
- 決まりを実行ファイルに任せるリポジトリーでは、サーバーが、指示の最後に `core` を足します。そのため、埋め込みの指示には、依頼の届き方と返事の扱いのような、窓口の会話に固有のことだけを書きます。タスク、目的に合わせること、わたしのこと、ブラウザーで読むことのような、どの会話にも当てはまる決まりは `core` に置き、同じ会話に2回届かないようにします。
- 会話を始めるとき、現在の実行ファイルと記録のリポジトリーから決まりを読みます。実行ファイルを差し替えると、その後に始まる会話から新しい決まりが届きます。読み出せないときは、動いているサーバーに入っている決まりを使います。
- 決まりを自分で持つリポジトリーでも、サーバーは本人の呼び名と相手のプロファイルの呼び名を埋め、共通の呼び方と宛先の決まりを添えます。タスク管理など、埋め込みの `core` の残りの節は足しません。

すでに動いている会話は、次の依頼を受け取るときに、変わった決まりの文書を知らされます。日付や記憶のファイルが変わったことだけでは通知しません。最初にこの仕組みを入れるときは、サーバーの更新が要ります。

依頼の渡し方は、[依頼の受付](requests.md)にあります。
