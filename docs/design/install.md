# 導入と更新

端末にレイシアを入れ、新しい版にし、取り除くまでの仕組みです。`lacia setup`、`lacia update`、`lacia uninstall` と、`lacia doctor` の端末の点検を説明します。使う方に向けた手順は、GitHub でリポジトリーを作るところから、[導入の案内](../install-guide.md)に書いています。

## 全体の流れ

導入の入口は2つあり、どちらも最後に `lacia setup` を呼びます。

| 入口 | すること |
| --- | --- |
| 導入のスクリプト（`install.sh`） | リリースのビルドを取得して照らし、その実行ファイルの `lacia setup` を呼びます（[導入のスクリプト](#導入のスクリプト)） |
| クローンして `make install` | 本体のクローン（`~/.lacia/src` をすすめます）で、手元の Go でビルドし、その実行ファイルの `lacia setup` を呼びます |

`lacia setup` は、端末を、引数が示す状態にそろえるコマンドです。何度実行しても構いません。

1. `git` を使えるかを確かめます。macOS で使えないときは、Xcode のコマンドラインツールを入れる画面を開いて止まります。
2. 動いている実行ファイルを `~/.lacia/bin/lacia` に置き、`~/.local/bin/lacia` をそこへのリンクにします。置き換える前の実行ファイルは、`lacia.previous` として残します。新しいファイルは一時の名前で書いてから名前を付け替えるので、その瞬間に起動したサーバーも、どちらかの版を丸ごと読みます。
3. 端末の設定（`~/.lacia/config/lacia.conf`）に `root` がなければ、はじめての導入として、記録を用意します（[記録を用意する](#記録を用意する)）。設定があれば、何も尋ねません。
4. OAuth クライアントを渡されたら、`~/.lacia/config/google-client.json` に置きます（[社内用の OAuth クライアント](#社内用の-oauth-クライアント)）。
5. macOS では、ログインのときにサーバーが起動するよう登録します（[常駐](#常駐)）。
6. 通知アプリを入れるよう頼まれたときと、入っている通知アプリを新しい版にするときは、作り直します（[通知アプリ](#通知アプリ)）。
7. 記録の場所、Web の画面のアドレス、端末の設定、ログの場所と、夜の処理がどう動くかを表示します。夜の処理の説明は、`lacia config` と同じものです。はじめての導入なら、ブラウザーでホームの画面を開きます。

| 引数 | 意味 |
| --- | --- |
| `--repo <URL>` | 記録のリポジトリーです。省くと尋ねます |
| `--dir <場所>` | 記録を置く場所です。省くと、ホームの下のリポジトリーと同じ名前の場所を示して尋ねます |
| `--name <呼び名>` | わたしがオーナーさんを呼ぶ名前です。新しい記録のときだけ使います。省くと尋ねます |
| `--addr <アドレス>` | 新しく書く端末の設定に、待ち受けるアドレスを書きます |
| `--google-client-id`、`--google-client-secret` | 予定の連携に使う OAuth クライアントです |
| `--notifier` | 通知アプリも入れます |
| `--no-autostart` | ログインのときにサーバーを起動する登録をしません。登録があれば外します |
| `--no-open` | 終わったあとに、ブラウザーを開きません |

質問は、標準入力がターミナルでなければ `/dev/tty` から読みます。スクリプトをパイプで `sh` に渡したときも、尋ねられます。すべてを引数で渡すと、何も尋ねずに進みます。

## 導入のスクリプト

`install.sh` は、本体のリポジトリーの最上位にあり、`https://raw.githubusercontent.com/imos/lacia/main/install.sh` から取得されます。することは、次の4つだけです。

1. `uname` で、OS と CPU の種類を確かめます。リリースがあるのは、Apple シリコンの Mac（`Darwin/arm64`）だけです。ほかの端末では、クローンして `make install` する経路を案内して止まります。
2. 最新のリリース（`https://github.com/imos/lacia/releases/latest/download/`）から、チェックサムの一覧（`SHA256SUMS`）と、その端末向けの実行ファイルを、一時のディレクトリーへ取得します。`curl` には、HTTPS と TLS 1.2 以降だけを使わせます。リダイレクトの先も同じです。
3. 実行ファイルの SHA-256 を、一覧の同じ名前の行と比べます。一覧にないときと、合わないときは止まります。
4. 実行ファイルの `lacia setup` を呼びます。スクリプトに渡した引数（`sh -s -- --repo …`）は、そのまま渡ります。`LACIA_GOOGLE_CLIENT_ID` と `LACIA_GOOGLE_CLIENT_SECRET` は、環境変数のまま `lacia setup` に届きます。

- 全体を関数に入れて、最後の行で呼びます。取得が途中で切れたスクリプトが、半分だけ動くことを防ぎます。
- 質問はしません。管理者の権限を使わず、シェルの設定も書き換えません。書くのは一時のディレクトリーだけで、終わると消します。
- `LACIA_DOWNLOAD_URL` で、取得する場所を変えられます。テストが、手元に立てた偽のリリースを使うためのものです。`https://` のほかには、`127.0.0.1` と `localhost` の `http://` だけを受け付けます。
- テスト（`install_test.go`）は、偽のリリースと、呼ばれ方を書き残すだけの実行ファイルで、照合が合うときに `lacia setup` が引数と環境変数を受け取ること、合わないときと一覧にないとき、リリースのない端末では止まることを確かめます。

チェックサムが防ぐのは、取得の途中の壊れだけです。一覧は実行ファイルと同じリリースにあるので、リリースのファイルを差し替えられる相手は、一覧も差し替えられます。これは、[リリース](#リリース)の成果物の証明と、同じファイルになるビルドで補います。

## 記録を用意する

| 確かめること | 結果と、そのあとの動き |
| --- | --- |
| リポジトリーに届くか（`git ls-remote`） | 届かなければ、`gh auth login` と `gh auth setup-git` を実行して HTTPS の URL でやり直すよう案内して止まります |
| 公開になっていないか | GitHub のリポジトリーを、ログインの情報を使わずに読めたら、公開とみなして止まります。SSH の URL は、HTTPS の形に直して確かめます。GitHub のほかと、手元のパスは、確かめません |
| 置く場所 | `~/Documents`、`~/Desktop`、`~/Downloads`、iCloud Drive（`~/Library/Mobile Documents`）の下と、ホームそのもの、`~/.lacia` の下は断ります。同じリポジトリーのクローンがすでにあれば、そのまま使います。空でないほかのものがあれば止まります |
| 中身 | 空なら、クローンして、記録の初期の中身を置き、`main` に最初のコミットを作ってプッシュします。レイシアの記録（`.lacia/config.json` があります）なら、クローンするだけで、何も書きません。ほかの中身があれば止まります |

- 中身は、`~/.lacia/tmp/` に浅くクローンして確かめ、確かめたら消します。レイシアの記録でないリポジトリーを、記録の場所へクローンしないためです。
- 断る場所の理由は2つです。macOS は、これらの場所に触るプログラムに許可を求めます。その場かぎりの署名の実行ファイルは、版が変わるたびに別のプログラムとみなされるので、更新のたびに許可を求め直されるとみています。iCloud の同期と、自動でコミットするサーバーが、同じファイルを別々に書き換えるおそれもあります。
- Git に名前とメールアドレスが設定されていない端末では、その記録のコミットにだけ「Lacia <lacia@localhost>」を設定します。サーバーは自分でコミットするので、名前がないと保存が止まるためです。
- 端末の設定には、`root`、`git-sync = true` と、見つかった会話の道具を書きます。Codex があれば `codex = codex`、なければ Claude Code があれば `claude = claude` です。どちらもなければ、書かずに知らせます。

### 記録の初期の中身

初期の中身は、本体の `internal/starter/files/` にあり、実行ファイルに入っています。以前のひな形のリポジトリーから、道具のファイル（`Makefile`、`tools/`、`LACIA_SOURCE`、`LACIA_VERSION`）、`README.md`、`LICENSE` を除いたものです。記録には、道具を置きません。

- いまの中身は、個人向けのひな形（imos/lacia-template）の `1d0ef35`（2026-11-27）に合わせています。ひな形とわざと違えているのは、導入の案内を `lacia setup` に合わせた3つのファイル（`.lacia/serve.conf`、`memory/accounts.md`、`memory/profile.md`）だけです。ひな形を読み取り専用にするまでに、ひな形の中身が変わったときは、このコミットからの差分を見て、ここへ写し、このコミットの記録も新しくします。
- 付属する定期タスクは、`S0001`（止めてある例）と `S0002`（毎日10時の `local/` の点検）です。番号の決め方は、[記録のリポジトリー](records.md#定期タスク)にあります。
- 呼び名は、`.lacia/config.json` の `user` と、`memory/profile.md` の「呼び名」の行に入れます。
- 初期の中身のファイルは、本体のほかの部分と違い、MIT No Attribution（MIT-0）で使えます。条文は `internal/starter/LICENSE` にあります。記録に `LICENSE` を置かなくても、オーナーさんは自由に使えます。本体のライセンス（`LICENSE`）にも、「記録の初期の中身」の節で、同じことを書いています。
- 初期の中身を直しても、すでにある記録には届きません。

### 社内用の OAuth クライアント

予定の連携に、組織のクライアントを使うときは、ID とシークレットを渡します。導入のスクリプトや `make install` には、環境変数 `LACIA_GOOGLE_CLIENT_ID` と `LACIA_GOOGLE_CLIENT_SECRET` で渡します。`lacia setup` を直接実行するときは、引数でも渡せます。

`lacia setup` は、Google の「インストール済みアプリ」の形の JSON を、`~/.lacia/config/google-client.json` に、持ち主だけが読める権限で書き、端末の設定に `google-client` の行を足します。記録の外に置くので、写しが記録のリポジトリーに増えません。このクライアントはデスクトップアプリの種類で、Google はそのシークレットを秘密として扱いません（[予定の連携](calendar.md)）。そのため、環境変数と引数から受け取ります。

## 常駐

macOS では、`~/Library/LaunchAgents/jp.imoz.lacia.serve.plist` に定義を書き、launchd に登録します。以前のひな形の `make autostart` と同じ名前なので、ひな形から入れた端末の登録は、新しい定義に置き換わります。環境変数 `LACIA_LABEL` で、試すための別の名前を使えます。

- 起動するのは `~/.lacia/bin/lacia serve --config <端末の設定>` です。シェルを挟まないので、macOS の「ログイン項目」には `lacia` の名前で並びます。版の入らない決まったパスなので、更新のたびに登録し直さずに済みます。
- launchd は、シェルの設定を読みません。常駐の `PATH` は、そのままでは `/usr/bin:/bin:/usr/sbin:/sbin` だけで、Codex、Claude Code、`gh` が見つかりません。定義には、`lacia setup` を実行したターミナルの `PATH` と `LANG`、`HOME` を書きます。
- サーバーの出力は、`~/.lacia/logs/serve.log` に書きます。サーバーは、起動のときにこのファイルが 10 MiB を超えていたら、`serve.log.1` へ移して、新しいファイルに書きます。古い分は1つだけ残します。
- 定義がすでに登録されているときは、中身が変わったときだけ書き直します。新しい定義は、次のログインから使われます。実行ファイルを置き換えたときは、動いているサーバーに、処理が終わったら起動し直すよう頼みます（`lacia restart --when-idle` と同じ）。launchd が、新しい版で起動し直します。
- 同じ名前のファイルに、別のものが書いた定義があれば、触らずに止まります。
- macOS のほかでは、登録せずに、起動のしかたを表示します。

## 通知アプリ

`lacia setup --notifier` は、実行ファイルに入っている通知アプリのソース（`macos/notifier/`）を `~/.lacia/tmp/notifier/` に書き出し、`manage.py` でビルドして入れ、起動します。入っている本体と同じ版のソースで、取得のための通信は要りません。ビルドには Xcode のコマンドラインツールが要ります。通知アプリがすでに入っていれば、設定を残したまま入れ替えます（`manage.py upgrade`）。実行ファイルを置き換えた `lacia setup` も、通知アプリが入っていれば、同じように作り直します。

## 更新

`lacia update` は、導入のときと同じ入口をもう1度実行します。

| 端末 | すること |
| --- | --- |
| `~/.lacia/src` がある | 手元の変更がなく、追跡するブランチがあれば `git pull --ff-only` で新しくしてから、`make install` を実行します。手元の変更があれば、取得せずに、いまあるものをビルドします |
| `~/.lacia/src` がない | 導入のスクリプトを取得して実行します |

どちらも、最後に新しい実行ファイルの `lacia setup` が動き、[全体の流れ](#全体の流れ)の2、5、6、7を行います。1つ前の版へ戻すコマンドはありません。`mv ~/.lacia/bin/lacia.previous ~/.lacia/bin/lacia` のあとに `lacia restart --when-idle` を実行します。

## 取り除き

`lacia uninstall` は、次のものを消します。記録と、GitHub のリポジトリーは残します。消す前に一覧を出して、`yes` の入力を求めます。`--yes` を付けると尋ねません。

- ログインのときにサーバーを起動する登録と、その定義のファイル
- 通知アプリと、その常駐の登録と、設定（`manage.py uninstall --remove-state`）
- `~/.local/bin/lacia` のリンク。`~/.lacia` を指すリンクのときだけ消します
- `~/.lacia`。`~/.lacia/src` がクローンへのリンクなら、リンクだけが消えます。クローンそのものに、コミットしていない変更があれば、`--yes` がない限り止まります

## リリース

版のタグ（`v0.1.0` のような形）をプッシュすると、`.github/workflows/release.yml` が、次の順に動きます。

1. 検査（`check.yml`）を、プッシュのときと同じ内容で走らせます。通らなければ、ビルドしません。
2. `make dist VERSION=<タグ>` で、実行ファイル（いまは `lacia-darwin-arm64` だけ）と、チェックサムの一覧（`SHA256SUMS`）を `dist/` に作ります。
3. 公開のリポジトリーでは、一覧に載せたファイルに、GitHub の成果物の証明（どのリポジトリーの、どのワークフローの、どのコミットから作ったかを示す、署名の付いた記録）を付けます。GitHub は、個人の無料と Pro のプランでは、非公開のリポジトリーに証明を付けられません。そのため、開発用のリポジトリーでは、この段を飛ばします。
4. タグの名前で、リリースを作って公開します。`gh release create` は、下書きにファイルを載せ終えてから公開するので、変えられないリリースの設定を入れても、ファイルがそろった状態で公開されます。

手で実行（workflow_dispatch）すると、1から3までを行い、リリースは作らずに、`dist/` をその実行の成果物として残します。ビルドを試すためのものです。版は、入力の `version`（既定は `v0.0.0-try`）です。

### 同じファイルになるビルド

`make dist` のビルドは、コミット、版、Go の版だけで決まるようにしています。

- Go の版は、`go.mod` の `toolchain` の行で1つに決めています。`make dist` は `GOTOOLCHAIN` にこの版を指定するので、手元の Go が別の版でも、Go がその版を取得して使います。
- `CGO_ENABLED=0` と `-trimpath` でビルドします。C のコンパイラーと、ビルドした場所のパスが、ファイルに入りません。
- 版は `-ldflags "-X main.release=<版>"` で入れます。`lacia version` と `lacia doctor` に出ます。
- `-buildvcs=true` で、コミットを実行ファイルに入れます。コミットしていない変更があると、実行ファイルに「変更あり」の印が入って、同じファイルになりません。`make dist` は、変更のあるクローンでは止まります。

このため、同じタグのクローンで `make dist VERSION=<タグ>` を実行すると、リリースと同じ `SHA256SUMS` ができます。2026-11-28 に、開発用のリポジトリーの同じコミットで、GitHub Actions（Linux）の手での実行が作った `lacia-darwin-arm64` と、Apple シリコンの Mac（macOS 26.5.1、手元の Go は 1.26.5 で、`GOTOOLCHAIN` が 1.26.11 を取得しました）で作ったものを比べ、1バイトも違わないことを確かめました。同じ日に、配布用のリポジトリーの最初のリリース（`v0.1.0`）でも、GitHub Actions が作った `SHA256SUMS` と、同じタグを Mac でビルドしたものが同じになりました。

リリースと手元のビルドの突き合わせは、`make verify` で行います。配布用のリポジトリーのクローンで、版のタグを取り出してから実行します。

```sh
git clone https://github.com/imos/lacia.git && cd lacia
git checkout v0.1.0
make verify
```

`make verify` は、次の3つを確かめます。どれかが合わなければ、そこで止まります。

1. `make dist` で作った `SHA256SUMS` が、リリースの `SHA256SUMS` と同じであること。同じなら、リリースの実行ファイルは、公開のソースからできたものと同じです。
2. `gh attestation verify` で、実行ファイルに、配布用のリポジトリーのワークフローが作ったという証明が付いていること。
3. `gh release verify` で、リリースが変えられない状態で公開されていること。

版は、取り出したタグから決まります。`VERSION` で指定することもできます。比べる相手のリポジトリーは `REPO`（既定は `imos/lacia`）で変えられます。`gh` が要ります。開発用のリポジトリーには版のタグがないので、開発用のクローンでは止まります。

### 画像の置き場所

導入の案内の画像は、`docs/images/` に置きます。合わせて 1 MiB までで、超えるとテスト（`install_test.go`）が失敗します。本体のクローンが、画像で大きくなりすぎないようにするためです。画像は、何も入っていない Mac で通して確かめるときに、手で撮ります。重点は、GitHub へつなぐ手順、非公開で空のリポジトリーを作る画面、macOS の確かめの画面（コマンドラインツールの導入、ターミナルへの貼り付けの確かめ、バックグラウンド項目の通知）の順です。`docs/design/` は実行ファイルに入るので、画像は置きません。

## 端末の点検

`lacia doctor` は、記録の形の点検に続けて、記録がこの端末の設定の `root` と同じで、読み取り専用のコピーでないときに、端末も点検します。

はじめに、版、記録と端末の設定とログの場所、サーバーが応えるか、最後にプッシュしたコミットの時刻、夜の処理がどう動くか（`lacia config` と同じ説明）を出します。会話か夜の処理に Claude Code を使う端末では、ログインに期限があり、常駐のサーバーはログインし直せないことも出します。期限そのものは、Claude Code が自分で知らせます。

続けて、直すことを、直すためのコマンドと一緒に挙げます。

| 点検 | 直し方の例 |
| --- | --- |
| 端末の設定が、以前の版の置き場所にある | 移すためのコマンド |
| 常駐の `PATH` で、設定した Codex や Claude Code が見つからない | `lacia setup`（いまの `PATH` で定義を書き直します） |
| Codex も Claude Code も設定していない | 端末の設定に書いて、`lacia setup` |
| `lacia` がシェルの `PATH` にない | `~/.local/bin` を `PATH` に足す行 |
| ログインのときにサーバーを起動する登録がない（macOS） | `lacia setup` |
| サーバーが応えない | ログを見る |
| `git-sync` のとき、記録をプッシュできない（`git push --dry-run`） | `gh auth login`、`gh auth setup-git`、取得先を HTTPS にするコマンド |

多くの項目には、[導入の案内](../install-guide.md#困ったとき)の該当する節へのリンクを添えます。`lacia doctor` は「案内:」の行に、ホームの画面は「案内を読む」のリンクに出します。リンクの先は公開の配布用のリポジトリーの `main` で、節の見出しが変わっていないことは、テスト（`TestGuideSections`）が確かめます。

直すことがあると、終了コードは1です。

サーバーも、上の表の最初の3つを、起動のあと10分ごとに確かめます。見つかったときだけ、Web のホームの画面のいちばん上に「この端末で直すこと」として出します。ほかの4つは、ターミナルからでないと分からないので、`lacia doctor` だけが確かめます。
