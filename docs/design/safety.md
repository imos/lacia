# 安全のための仕組み

会話は、自分で判断して、ファイルを書き、コマンドを実行します。そのため、判断に任せられないことは、サーバーとコマンドの側で守っています。この文書では、同じ書き込みの繰り返しへの備え、秘密の扱い、制限を会話が緩められないようにする作り、本体が外へ作用する処理を集める場所、ブラウザーの使い方の境界を説明します。

## コミットの数に上限を置く

サーバーは、書き込みがあると、5秒待ってから Git へ保存します。そのままだと、10秒おきに同じタスクへ書き続けるスクリプトがあれば、そのたびにコミットが増えます。

サーバーは、各タスクの変更を続けて10回までコミットできます。コミットして使った回数は5分に1回分ずつ回復します（`internal/gitsync`）。

上限に達したタスクだけが変わったときは、次にコミットできるまで変更をまとめておきます。同じタスクだけに書き続けた場合、最初の10回を使ったあとは、1時間に12回までです。まだ上限に達していない別のタスクにも変更があれば、待っていた分も一緒にコミットします。サーバーが止まる前の最後の保存は、この上限にかかわらず行います。

ファイルと画面には、コミットを待つあいだも変更が表れます。読み取り専用のコピーは Git から取り込むので、コミットを待つ分だけ、変更が届くのが5分ほど遅れることがあります。

## 同じ書き込みの繰り返しを止める

サーバーは、`lacia` コマンドからの書き込みを、タスクと、書き込んだ元の組ごとに数えます（`internal/web/flood.go`）。数えるのは、次の4つです。

- 履歴への記録（`lacia task note`）
- ファイルを置くこと（`lacia task attach`）
- 本文と補足の書き換え（`lacia task write`）
- タスクを指定した依頼（`lacia ask --task`）

書き込んだ元は、会話ごとに分けます。会話から呼ばれていないコマンドは、まとめて1つの元として扱います。

次のどちらかに当たると、繰り返しと判断します。

- 30分のあいだに同じ中身の書き込みが10回届いたときです。同じ中身とは、同じ文の記録、同じ名前で同じ内容のファイル、同じ文の依頼のことです。
- 書き込みの中身にかかわらず、30分のあいだに1000回に達したときです。

繰り返しと判断したときに、サーバーが行うことは、次のとおりです。

1. その元からそのタスクへの書き込みを、30分のあいだ断ります。断るときは、理由と、いつまで止めるのかを返します。
2. 履歴に、止めたことと理由を、1行だけ書きます。
3. タスクが閉じていなければ、確認待ちへ出します。進行中でも出します。繰り返しは自然には止まらないので、オーナーさんに見てもらう必要があるためです。
4. タスクに `stopped_at`（止めた時刻）を書きます。Mac の通知アプリを使っていれば、「繰り返しの書き込みを止めました」と知らせます。

止めるのは、繰り返している元と、そのタスクの組だけです。

- Web の画面からの操作は、止めません。
- ほかの会話からの書き込みと、ほかのタスクへの書き込みは、止めません。
- 状態や項目の変更（`lacia task set`、`lacia task field`）は、数えません。ただし、止めている30分のあいだは、同じ元からの、そのタスクの状態や項目の変更も、断ります。

30分たつと、その元からの書き込みを、また受け付けます。繰り返しが続いていれば、また止まって、もう1度知らせます。`stopped_at` は、だれかがタスクの状態を変えると、消えます。数えた記録はサーバーのメモリーにだけあり、サーバーを起動し直すと、数え直しになります。

数は、ふつうの作業では届かない値にしています。報告を直しながら、同じファイルを数回置き直す、といった作業では、止まりません。使ってみて合わなければ、変えます。

## 秘密の扱い

- 認証の情報、トークン、認証コードは、Git にも、ログにも、書きません。記録のリポジトリーにも、コードのリポジトリーにも、置きません。
- サーバーが持つ秘密は、`state` のディレクトリーに置きます。Google の許可の情報（`secrets/gcal.json`）が、これに当たります。`state` は、記録のリポジトリーの外に置きます。
- Discord のトークンは、環境変数か、ファイルの場所で渡します。設定ファイルには書きません。
- 予定の説明文、参加者、会議のアドレスは、保存しません。通知の記録には、予定の題名を書きません。
- 一時的なデータや大きなファイルは、記録のリポジトリーの `local/` に置きます。`local/` は、`.gitignore` で Git から外しておきます。

## 制限される側が、制限を緩められない作り

会話は、記録のリポジトリーへ書き込めます。そのため、会話が書ける場所から、会話を縛る設定を変えられないようにしています。

- 記録のリポジトリーの `.lacia/serve.conf` で指定できるのは、プロファイルの呼び名や予定の連携などに限ります。待ち受けるアドレス、起動するコマンド、サンドボックス、プッシュ、Discord などは、コマンドラインか、リポジトリーの外の設定ファイルで指定します（[設定の一覧](settings.md#記録の側に置ける設定)）。
- Discord で受け付ける人の対応表は、記録のリポジトリーの外に置きます（[Discord からの受付](discord.md#対応表discord-members)）。
- 設定を省いたときや、サーバーが知らない設定名を読み飛ばしたときも、受け付ける操作の範囲は広がりません。
- 相手のプロファイルへの伝言が、だれの言葉なのかは、サーバーが決めます（[複数のプロファイル](profiles.md#だれの言葉かをサーバーが決める)）。
- Web の画面は、別のサイトからの、状態を変える要求を断ります。成果物の HTML は、画面から切り離して表示します（[記録のリポジトリー](records.md#成果物の置き場所)）。

外部への送信、共有、申請、購入を、その依頼で許可されているときだけ行う、という決まりは、会話の側の決まりです（`lacia rules permissions`）。サーバーは、これを仕組みでは止めていません。

## 外へ作用する処理を集める場所

本体が外に対して何をしうるかを、少ないファイルを読むだけで言えるようにするため、外へ作用する処理を、決まったパッケージに集めます。コメントで「安全です」と書いても、安全であることは示せません。そこで、集まっていることを、テストで確かめます。

| 種類 | 受け持つパッケージ | 読めば分かること |
| --- | --- | --- |
| 外部のコマンドの起動 | `internal/effect/program` | 起動してよいコマンドの一覧が、`list.go` の1つのファイルに並んでいます |
| ファイルへの書き込み | `internal/effect/disk` | 書いてよい場所と、その外に書く2つのファイルが分かります |
| 外への通信 | `internal/effect/network` | インターネットで通信してよい先の一覧が、`hosts.go` の1つのファイルに並んでいます |

新しく書くコードは、はじめからこのパッケージを使います。既存のコードは、まだ多くが自前で起動や書き込みをしています。少しずつ移していきます（[境界のテスト](#境界のテスト)）。

### 外部のコマンドの起動

ほかのパッケージは、`program.Git()` や `program.Codex(path)` のように、`list.go` にある関数からしか、起動するコマンドを作れません。起動のたびに、そのコマンドが何のためのものかが、コードに表れます。

| 一覧の分け方 | コマンド |
| --- | --- |
| macOS に入っている道具。決まったパスで起動するので、`PATH` で差し替えられません | `caffeinate`、`launchctl`、`xcode-select`、`open`、`curl`、`sh`、`make`、`python3` |
| `PATH` から探すもの | `git`。新しい版を自分で入れている方がいるためです |
| 入れる場所を、オーナーさんが選ぶもの。場所は、コマンドラインか、記録の外の設定から渡します | `kubectl`、Codex、Claude Code、決まった時刻の仕事の前に認証を確かめる、設定に書いたコマンド |
| `lacia` 自身 | 動いている実行ファイルか、配備で置き換えた実行ファイル |
| 利用者のシェル | 環境変数 `SHELL` のシェル。絶対パスでなければ `/bin/sh` です。`lacia shell` が使います |

コマンドを起動したあと、そのコマンドが何をするのかまでは、このパッケージでは決まりません。たとえば、`git` は記録のリポジトリーへ書き込み、Codex と Claude Code の会話は、自分で判断してファイルを書き、コマンドを実行します。会話を縛る仕組みは、この文書のほかの節と、[ログインの違う Codex を呼び分ける](logins.md)にあります。

### ファイルへの書き込み

本体が書いてよい場所は、2つです。

- 記録のリポジトリー（`disk.OpenRecords`）
- 道具の置き場所の `~/.lacia`（`disk.OpenTools`）。サーバーの状態とログも、ここに置きます。秘密を含むので、作るディレクトリーは、オーナーさんだけが読めるようにします。

どちらも、Go の `os.Root` で開きます。ファイルの名前は、開いたディレクトリーからの相対の名前で渡します。`..` や、外を指すシンボリックリンクをたどる名前は、`os.Root` が断ります。

この2つの外に本体が書くのは、次の2つだけです。どちらも、`internal/effect/disk/install.go` に、決まったパスで書いてあります。

- 常駐の定義の1ファイル（`~/Library/LaunchAgents/<名前>.plist`）
- `~/.local/bin/lacia` のリンク。消すときは、リンクのときだけ消します。ほかの方が置いた実行ファイルは消しません。

`lacia uninstall` は、`~/.lacia` を丸ごと消します（`disk.RemoveTools`）。名前が `.lacia` か、`LACIA_HOME` で指定した場所でなければ、消しません。

起動したコマンドは、この外にも書きます。`lacia setup` では、`git` が、オーナーさんの選んだ場所へ記録をクローンし、通知アプリの `manage.py` が、アプリと、その常駐の定義と設定を置きます。`lacia update` では、`curl` が導入のスクリプトを `~/.lacia/tmp/` へ取得し、`make` がクローンでビルドします（[導入と更新](install.md)）。

ファイルの中身を丸ごと置き換えるときは、`WriteFile` を使います。一時ファイルに書いて、ディスクへの書き出しを済ませてから名前を付け替え、ディレクトリーも書き出します。読む側には、古い中身か新しい中身のどちらかが見え、途中まで書いたファイルは見えません。この処理は、このパッケージに1つだけ置きます。頻繁に書き、失っても困らないファイルには、ディスクへの書き出しを待たない `WriteFileNoSync` を使います。こちらは、クラッシュのあとに空のファイルが残ることがあります。ほかに、追記（`Append`、`OpenAppend`）、まだないファイルだけを作る書き込み（`CreateNew`）、ディレクトリーを作る、名前を変える、消す、があります。書き込みのときは、足りない親のディレクトリーも作ります。

サーバーの状態のファイルのように、`Dir` ではなくファイルのパスを持っているコードは、パッケージの関数の `WriteFile`、`WriteFileNoSync`、`Append`、`Remove`、`MkdirAll` を使います。そのファイルのディレクトリーを `os.Root` で開いて、その中に書きます。足りないディレクトリーは、ファイルを読める人が開けるように作ります。`0o644` のファイルなら `0o755`、`0o600` のファイルなら `0o700` です。この形では、どのディレクトリーに書くかは、呼ぶ側が渡すパスで決まります。記録と道具の置き場所を開いた `Dir` を渡す形にそろえるのは、これからの仕事です。

### 外への通信

本体が開く接続は、行き先で3つに分かれます。どれも、このパッケージの関数で作ります。

| 行き先 | 使う関数 | 行き先の決まり方 |
| --- | --- | --- |
| インターネットのサービス | `network.Internet`、`network.WebSocket` | `hosts.go` の一覧にあるホストだけです。いまは、Discord の API（`discord.com`）、Discord の出来事を受け取る接続（`*.discord.gg`）、Discord に添付された画像（`cdn.discordapp.com`）、Google のトークンと Google カレンダー（`oauth2.googleapis.com`、`www.googleapis.com`）です |
| lacia のサーバー | `network.Server`、`network.ServerRestarting` | オーナーさんが設定で決めます。手元のサーバー、別のプロファイルのサーバー、予約の仕事を渡すサーバーが当たります |
| この機械の中のソケット | `network.Listening`、`network.SocketWebSocket` | Codex の app-server のソケットです |

`network.Internet` の通信は、一覧にないホストへは、送る前に失敗します。転送（リダイレクト）の先も同じです。この機械の中（`localhost` と、ループバックのアドレス）は、外ではないので通します。テストは、ここに偽のサービスを置いて試します。

GitHub には、`git` と `curl` が通信します。どちらも、`internal/effect/program` が起動します。Google の同意の画面（`accounts.google.com`）は、利用者のブラウザーが開きます。Web の画面のサーバーが待ち受けて、届いた要求に答えることは、外への通信には入りません。

### 境界のテスト

`internal/effect/boundary_test.go` が、本体のソースを構文として読み、外へ作用する処理が、受け持つパッケージの外にないかを確かめます。読むのは、テストを除く Go のファイルです。開発のための道具（`tools/`）と、`testdata` は読みません。

| 種類 | 見つけ方 |
| --- | --- |
| 外部のコマンドの起動 | `os/exec` の名前を使う箇所と、`syscall.Exec` の仲間、`os.StartProcess`。`os/exec` を読み込むのは、`internal/effect/program` だけにします |
| ファイルへの書き込み | `os.WriteFile`、`os.Create`、`os.CreateTemp`、`os.Rename`、`os.Remove`、`os.RemoveAll`、`os.Mkdir`、`os.MkdirAll`、`os.Symlink`、`os.Chmod`、`os.OpenRoot` などを使う箇所と、書き込みのフラグを付けた `os.OpenFile` |
| 外への通信 | `http.Get` などの関数、`http.DefaultClient`、`http.DefaultTransport`、`http.Client` や `http.Transport` を作る箇所、`net.Dial` の仲間、`websocket.Dial`。要求を作る `http.NewRequest` は数えません。送るのは、このパッケージで作ったクライアントだけだからです |

`os` はどのパッケージも読み込み、`net/http` は Web の画面の側も読み込みます。そのため、書き込みと通信は、読み込みではなく、関数を使う箇所で見分けます。

既存のコードのうち、まだ移していない箇所は、`internal/effect/exceptions_test.go` の例外の一覧に、ファイルと箇所の数で載せています。

- 載っていないファイルに見つかったときと、載っている数より増えたときは、テストが失敗します。受け持つパッケージを使うように直します。
- 載っている数より減ったときも、テストが失敗します。一覧の数を下げるためです。下げずにおくと、次に増えたときに見逃します。
- 失敗したときは、いまの数を、一覧にそのまま貼れる形で表示します。

2026-11-28 に一覧を作ったときの数です。移し終えると、一覧は空になります。

| 種類 | ファイル | 箇所 |
| --- | ---: | ---: |
| 外部のコマンドの起動 | 15 | 27 |
| ファイルへの書き込み | 44 | 166 |
| 外への通信 | 14 | 29 |

このテストは、ソースの書き方から見分けています。次のものは、見つけられません。

- `http.Client` を、値の宣言や `new` で作る書き方
- 同じ名前の変数で、パッケージの名前を隠した書き方
- 受け持つパッケージの外で、ほかの方法で手に入れたファイルへの書き込み。書き込みのために開くこと自体は、見つけます
- 起動したコマンドや会話が、そのあとで行うこと

## 実行ファイルに埋め込んだコマンド

`lacia` の実行ファイルには、会話が使う短いコマンドが、埋め込んであります（`cmd/lacia/shims/`）。

| コマンド | 役割 |
| --- | --- |
| `lacia-browse` | 公開のページを、ブラウザーで開きます（下の節） |
| `pre-push` | すべてのプッシュを断る、Git のフックです（[ログインの違う Codex を呼び分ける](logins.md#作業役)） |

- 依頼を受け付けるサーバーは、起動のときに、これらを `state` のディレクトリーの `bin/` へ書き出して、会話の `PATH` の先頭に足します。
- サーバーを動かさない環境では、`lacia shims <ディレクトリー>` で書き出せます。

### プッシュを止めるフック

`pre-push` は、どんなプッシュも断るフックです。別のログインで起動した Codex の作業役は、Git のフックの置き場所を、このフックのあるディレクトリーへ向けて起動されます。作業役が、成果を勝手にプッシュしないようにするためです。成果を保存するのは、呼び出した側だけです。

記録のリポジトリーについては、別の決まりがあります。コミットとプッシュをするのはサーバーだけで、会話はしません。手元の読み取り専用のコピーは、プッシュの宛先を無効にして、プッシュできないようにしておきます（[記録のリポジトリー](records.md#読み取り専用のコピー)）。

## ブラウザーの使い方の境界

`lacia-browse` は、ログインの要らない公開のページを、ブラウザーで開いて読むためのコマンドです。[playwright-cli](https://github.com/microsoft/playwright-cli) を呼びます。

```sh
lacia-browse read "https://example.com/page"   # 本文を文字で返して、閉じます

lacia-browse open https://example.com/
lacia-browse snapshot            # ページの構造と、要素の番号
lacia-browse fill e89 "検索する語"
lacia-browse click e120
lacia-browse close
```

- `read` は、開く、ページが落ち着くのを待つ、本文を返す、閉じる、を1回で行います。`lacia-browse` が足したコマンドです。ほかは、そのまま playwright-cli へ渡します。
- 開けないときは、90秒であきらめます。
- 閉じ忘れたセッションは、最後のコマンドから15分で、自動で閉じます（`LACIA_BROWSE_IDLE_MS`）。
- セッションの名前は、会話の ID から自動で付けます。会話どうしで、タブやクッキーを共有しません。

境界は、次のとおりです。

- **使ってよいのは、ログインの要らない、公開のページを読むことです。** ログイン、資格情報や個人の情報の入力、購入、予約、送信には、使いません。これは、いつも守る決まり（`lacia rules` の `core`）の「ブラウザーで公開ページを読む」に書いてある決まりです。手元で起動した会話にも、サーバーが起動する会話にも届きます。
- **環境変数を渡しません。** `lacia-browse` は、ブラウザーを起動するときに、環境変数を、`HOME`、`PATH`、`TZ`、`LANG` だけに絞ります。会話の持つ認証の情報が、ブラウザーへ渡らないようにするためです。
- **ブラウザー自身のサンドボックスを切りません。** 手元では、Chrome を、サンドボックスを有効にしたまま起動します。

サンドボックスを使えない環境（権限を絞ったコンテナーなど）では、同じ場所で Chrome を動かしません。ページが描画のプロセスを乗っ取った場合に、そのコンテナーの中の認証の情報を、すべて読めてしまうためです。その場合は、認証も、保存領域も持たない別のコンテナーで、Playwright のサーバーを動かして、`lacia-browse` をそこへつなぎます。

| 環境変数 | 意味 |
| --- | --- |
| `LACIA_BROWSER_ENDPOINT` | つなぐ先の Playwright のサーバーです。空にすると、手元の Chrome を使います |
| `LACIA_PLAYWRIGHT_CLI_VERSION` | 使う playwright-cli の版です。つなぐ先と、同じ版にします |

Kubernetes の中で動いているときは、`LACIA_BROWSER_ENDPOINT` の指定が要ります。指定がなければ、ページを開かずに止まります。サーバーの認証情報のそばで、Chrome を動かさないためです。

ブラウザーを動かす側のコンテナーの定義は、このリポジトリーにはありません。用意するときは、認証と保存領域を持たせないこと、内側のネットワークへ出られないようにすること、Playwright のサーバーを `--unsafe` なしで起動することを、守ってください。
