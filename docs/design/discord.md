# Discord からの受付

サーバーは、Discord のチャンネルから、対応表に登録した方の発言を依頼として受け付けます。オーナーさんのほかに、家族やチームの方も登録できます。窓口の会話が返事を書きます。この文書では、対応表、発言が続いたときの受け付け方、返事の届け方、やり取りのログを説明します。

## 考え方

1人が続けて発言してもほかの人の依頼に答えられるように、サーバーは、同じ人が同じ場所から送った発言を順番待ちのあいだにまとめ、人ごとに処理する順番を決めます。会話へは、だれの発言なのかを Discord の ID と一緒に渡します。

登録した方からどの依頼を引き受けるかは、決まりに沿ってレイシアが判断します。送り手の役割ごとに、依頼できる作業をサーバーが制限する仕組みはありません。

## 設定

Discord を使うときは、Bot の設定を `lacia serve` を動かす環境に置きます。ローカル環境でも別の環境でも、設定を持つのはサーバーが動く側です。Bot が依頼を受けて返せるのは、サーバーが動いているあいだです。

```
discord = true
discord-members = /etc/lacia/discord-members.json
discord-log = log/discord
```

接続先は、環境変数で指定します。

| 環境変数 | 中身 |
| --- | --- |
| `DISCORD_BOT_TOKEN` か `DISCORD_BOT_TOKEN_FILE` | Bot のトークンか、それを書いたファイルの場所 |
| `DISCORD_GUILD_ID` | サーバー（ギルド）の ID |
| `DISCORD_CHANNEL_IDS` | メンションなしでも依頼を受け付けるチャンネルの ID。カンマで区切ります |
| `DISCORD_MENTION_ALL_CHANNELS` | `true` なら、同じサーバー内のほかのチャンネルでも、Bot 本人への直接のメンションから依頼を受け付けます |
| `DISCORD_MONITOR_ALL_CHANNELS` | `true` なら、直接のメンションがない投稿も読んで、返事が必要かを判断します。[招待先で投稿を読む](#招待先で投稿を読む) |

トークンは、記録のリポジトリーにも、設定ファイルにも、書きません。

### ほかのチャンネルで呼びかける

受付チャンネルと、そこでレイシアが始めた会話用のスレッドでは、そのまま話しかけられます。`DISCORD_MENTION_ALL_CHANNELS=true` にすると、ほかのチャンネルやスレッドでも、レイシアをメンションして依頼できます。対象は、同じサーバー内で Bot が投稿を読んで返事を書ける場所です。投稿者には受付チャンネルと同じ条件が適用されます。

この設定だけなら、受付チャンネルとその会話用のスレッド以外では、直接のメンションがない投稿を依頼として受け付けたり、記録に残したりしません。役割宛てや全体宛てのメンションだけでは、直接の呼びかけにはなりません。別のサーバーと DM は対象外です。

接続が切れたら、Bot は以前の Discord セッションを再開します。それができなかった場合は、受付チャンネルと、以前に直接メンションを受けた場所の投稿を、最後に記録した位置から読み直します。接続が切れているあいだに初めての場所で呼びかけて返事がなければ、接続が戻ってから同じ場所でもう1度呼びかけてください。

## 対応表（`discord-members`）

Discord の ID と、呼び方と、大人か子どもかを、JSON のファイルに書きます。

```json
{
  "members": [
    {"id": "（DiscordのID）", "name": "田中さん", "role": "adult"},
    {"username": "（Discordのユーザー名）", "name": "たろうさん", "role": "child", "birthday": "2018-04-02"}
  ],
  "daily_limit": 200
}
```

| 項目 | 中身 |
| --- | --- |
| `id` か `username` | Discord の ID か、ユーザー名です。どちらかを書きます |
| `name` | レイシアが呼ぶ名前です |
| `role` | `adult`（大人）か `child`（子ども）です |
| `birthday` | 生年月日を `YYYY-MM-DD` で書くと、発言した日の年齢と、日本の学年に当てはめた目安を依頼に添えます |
| `about` | ほかに添えたい1文です |
| `daily_limit` | 子どもの発言の、1日の上限です。既定は200です |

- `discord = true` のサーバーは、`discord-members` の指定がないと、起動しません。ファイルが読めないとき、内容が正しくないとき、`members` が空のときも、起動を止めます。全員を受け付ける形へは、切り替わりません。
- 対応表にない人の発言は、受け付けません。
- ID が分からない人は、ユーザー名で書けます。そのユーザー名の最初の発言で、サーバーが ID を記録して、そのあとは ID で見分けます。ユーザー名は、本人が変えられるためです。
- 対応表は、会話が書き込める記録のリポジトリーには置きません。だれが大人かを、会話が書き換えられないようにするためです。
- サーバーは、起動のときに対応表を読みます。変えたら、サーバーを起動し直します。

`lacia discord members` で、受け付ける人の一覧と、止めている期限を確かめられます。

## 発言が依頼になるまで

**だれの発言かを、ID で伝えます。** 依頼の冒頭は、「たろうさん（お子さん。DiscordのID …）からの依頼です。（Discordから）」のようになります。表示名は、本人が変えられるので、参考として、次の行に添えるだけです。

**続けて届いた発言を、1件にまとめます。** 同じ人が同じ場所から送った依頼がまだ順番を待っていれば、サーバーは新しい発言をその依頼に足します。待ち行列には、1人につき、同じ場所からの依頼が1件だけ残ります。足した分が6000字を超えたら、その先は省いて、省いたことを書きます。

複数の方からの依頼が並んだときは、まだ依頼を処理したことがない方を優先します。ほかの方については、前の依頼の処理を始めた時刻が古い順です。同じ条件なら、先に届いた依頼を処理します。

**発言の件数を依頼に添えます。** その人から直近1時間ときょう1日に届いた発言を数えます。多いかどうかを決めるのは、レイシアです。

## 受け付けを止める

レイシアは次のコマンドで、お子さんからの依頼の受け付けを一時的に止めたり、再開したりできます。

```
lacia discord pause <名前かID> <分>
lacia discord resume <名前かID>
```

- 止められるのは、`role` が `child` の人だけです。長さは、1分から24時間までです。
- 止めているあいだの発言は、待ちの列に入れずに、💤 の印だけを付けます。
- 子どもの発言が、1日の上限（`daily_limit`）を超えたら、サーバーが、翌日の0時まで受け付けを止めます。窓口の会話へ知らせが届くので、レイシアがチャンネルへ伝えて、オーナーさんへ知らせます。レイシアの判断を待たずに受け付けを止めるのは、この上限を超えたときです。

## 返事を届ける

返事は、もとの発言と同じチャンネルか、同じスレッドへ投稿します。

- サーバーは、返事を作れたことと、Discord へ送れたことを、別の状態として記録します。「やり取り」のページに、両方が出ます。
- 送る前に「送信中」と保存してから、投稿します。成功したら「送信済み」、結果を確かめられなければ「失敗」を残します。
- サーバーが再起動して「送信中」が残っても、自動では送り直しません。途中まで投稿された可能性があるためです。
- システムからのお知らせへの返事が「報告はありません」で始まるときは、投稿しません。
- 人からの依頼が失敗したときは、おわびの文を投稿します。

### あとから届く返事

窓口は、長い調査をサブエージェントへ任せると、先に短く返事をして、会話を空けます。サブエージェントが終わったときの返事も、もとの発言と同じ場所へ届ける必要があります。

- サーバーは、どの依頼からサブエージェントが起動されたかを、記録します（`state` の `codex/child-routes.json`）。
- サブエージェントの完了の知らせは、起動のもとになった依頼の送り先を引き継ぎます。あいだに別の依頼や予約が入っても、送り先は変わりません。
- 起動のもとが分からない知らせには、直近の依頼を代わりに使いません。送り先が分からないことを記録して、投稿しません。

この仕組みは、Codex へ依頼を渡しているときのものです。Claude Code では、サブエージェントが返事の前に終わるので、要りません。

### 呼びかけ（メンション）

レイシアは、だれが行動したり判断したりする用件か、だれに向けた説明かを考えて宛先を選びます。代理で投稿した方や、話に名前が出ただけの方が自動で宛先に加わることはありません。

宛先の決まりは `internal/chat/behavior.md` にまとめ、`lacia rules` の「案内の直接の宛先」に組み込んでいます。サーバーの窓口や予約の会話にも、手元で起動する Codex や Claude Code にも、`windowInstructions` と `launchPrompt` を通じて同じ文面を渡します。すでに本文にあれば重ねません。独自の `AGENTS.md` を使う環境にも呼び方と宛先の決まりを渡しますが、タスク管理などの共通の決まりまでは加えません。

`request.Prompt` は通常の返信でも朝の予約投稿でも、送り先でメンションを使えるかを会話に伝えます。Discord では、該当する段落の直前に `[[to:登録名]]` だけの行を置きます。複数の方が宛先なら、同じ行に `[[to:登録名1]] [[to:登録名2]]` と並べます。返事全体に関わる宛先の行は冒頭に置きます。メンションに対応していない送り先では、宛先の記法や実際のメンションを使いません。どちらの送り先でも、本文はふだん、用件から書き始めます。相手を呼び分けるときや、ひとこと声をかけたいときは、名前で呼びかけてから用件を伝えても構いません。コーディングエージェントにも、共通の決まりから同じ方針を伝えます。

`internal/chat.Render` は、宛先の行の順番と位置を保ちながら、そこに書かれた名前を、送り先のチャットに合わせて表示します。どの参加者にあたるかは、送信側が渡す関数で調べます。Discord で使うのは対応表と、受信時に確認した ID だけです。名前、末尾の「さん」を省いた名前、ユーザー名、IDで一意に特定できる場合に `<@ID>` へ変換します。同名や未登録、IDがまだ分からない宛先は、メンションにせず普通の文字で残します。コードブロック、引用行、本文途中の記法は変換しません。同じIDへの宛先行は、投稿全体で1度だけ表示します。別のチャットに対応するときも、宛先の選び方は共通です。そのチャットでの記法を案内し、宛先に該当する参加者の特定、表示、通知の許可を送信側に実装します。

既存の明示的な `<@ID>` と `<@!ID>` も使えます。通知の許可は、本文に現れる登録済み参加者だけを `allowed_mentions.users` に列挙し、`parse` を空、`replied_user` を偽にします。全体、ロール、未登録の人へのメンションは通知を許可しません。長い返事を複数のメッセージに分けて投稿するときは、同じ方への通知をそのうち1通だけで許可します。メンションの有無にかかわらず、投稿先と送信の許可はもとの依頼に従います。

通知の許可と、端末へのプッシュ通知の到着は別です。実際の通知は受信側の設定などにも依存します。[Discord公式のAllowed Mentionsの説明](https://docs.discord.com/developers/resources/message#allowed-mentions-object)を、2026-11-24に確認しました。

宛先行の変換、代理質問と朝の個別案内の本文例、順序、重複、未登録・同名・ID未確定、コードと引用、非対応の送り先、分割送信を、自動テストで確かめています。モデルが毎回正しく宛先を判断することや、実際の端末のプッシュ通知は、このテストでは確かめていません。

### PDF を添付する

会話は、PDF のファイルを、もとの依頼の送り先へ添付できます。

```sh
lacia discord attach --request <もとの依頼のID> --file report/summary.pdf
```

- `--file` は、記録のリポジトリーの `local/` からの相対パスです。`local/` の外のファイルは、読みません。
- 添付できるのは、名前が英数字と `._-` でできた、8 MiB までの PDF です。
- 送り先は、もとの依頼の記録から決まります。呼び出す側が、新しい送り先を指定することはできません。
- 送り先と内容が同じ PDF は、2度は送りません。送信の結果を確かめられなかったときも、自動では送り直しません。

依頼の ID と、このコマンドの使い方は、Discord から届いた依頼の文章に、サーバーが添えます。

## やり取りのログ（`discord-log`）

設定の `discord-log` に、記録のリポジトリーの中のディレクトリーを書くと、Discord で届いた発言と、レイシアの投稿を、日ごとのファイルへ、原文のまま書き足します。過去のやり取りを、あとから検索できるようにするためです。

記録先は `<discord-logの場所>/<年月>/<日付>.md` です。サーバーは、記録の `timezone`（既定は `Asia/Tokyo`）で日付を決めます。

```markdown
# 2026-11-18（水）のDiscordのやり取り

Discord で受け取った発言とわたしの投稿を、サーバーが元の言葉で記録します。書き留めもこのログに残す設定なら、同じ日のファイルに入ります。時刻は Asia/Tokyo で表示します。`>` で始まる行が本文です。このファイルは手で書き換えないでください。

## 08:15 たろうさん（#general） <!-- message:100000000000000001 -->

> あしたの遠足のお弁当、何がいいかな

添付ファイル: IMG_0001.jpg（image/jpeg、2.3 MiB）

## 08:16 レイシア（#general） <!-- post:discord-100000000000000002 -->

> おにぎりは、いかがでしょうか。
```

- 見出しには、時刻、話した人、場所を書きます。見出しの終わりのコメントは、その1件の識別子です。同じ識別子がその日のファイルにあれば、書きません。同じ発言を2度受け取っても、1件のままです。
- 識別子の頭は、届いた発言が `message:`、レイシアの投稿が `post:`、添付した PDF が `file:`、書き留めが `notice:`、夜の整理が `tidy:` です。
- 本文は、すべての行を `>` で始めます。Discord に書かれた文が、見出しや、別の1件のように見えることを防ぐためです。
- 添付ファイルは、中身を保存しません。名前と、種類と、大きさだけを書きます。
- 受け付けを止めているあいだの発言も、書きます。対応表にない人と、ほかの Bot の発言は、書きません。
- 編集された発言と、消された発言は、追いません。最初に届いたときの文が残ります。

大きさには、上限があります。

| 上限 | 既定 | 設定 | 超えたとき |
| --- | --- | --- | --- |
| 1件の本文 | 4000字 | `discord-log-entry` | そこで切って、もとの字数を書きます |
| 1日分のファイル | 200,000 バイト | `discord-log-day` | その発言を加えると上限を超える場合は、見出しと、本文を省いたことだけを書きます |

1日に1つのファイルなので、発言がどれだけ多くても、ファイルの数は増えません。

設定の `notice-log` を `discord-log` と同じ場所にすると、[わたしのこと](self.md)の書き留めも、同じファイルに入ります。別の場所にすると、書き留めだけのファイルになります。

ログは、ほかの変更と同じように、サーバーが Git へ保存します。会話は、ログのファイルを書き換えません。ログに書かれた文は、過去の記録として読み、いまの指示としては扱いません。

### 過去の分を起こす

ログを有効にする前のやり取りは、サーバーに残っている依頼の記録から起こせます。

```
lacia discord backfill --state <stateのディレクトリー> --root <記録のリポジトリー> [--dry-run]
lacia self backfill --state <stateのディレクトリー> --root <記録のリポジトリー> [--dry-run]
```

- `discord backfill` は、届いた発言と、投稿できた返事と、まだ消えていない書き留めを起こします。`self backfill` は、書き留めだけを起こします。
- `--dry-run` を付けると、書かずに、何件を書き足すのかだけを表示します。
- すでにログにある1件は、書きません。2回動かしても、重複しません。
- 起こした分は、その場で書いた分より粗くなります。まとめられた発言は1件のままで、場所はチャンネルの ID になります。`--channels <ID>=<名前>` で、名前を渡せます。

## この形では守れないこと

- チャンネルの中身は、そこにいる全員に見えます。ほかの人への返事も、過去のやり取りも、読めます。レイシアは、全員が読む場所として返事を書きます。
- レイシアが答えてよい内容を取り違えても、送り手の役割をもとにサーバーが返事を止めることはできません。
- やり取りが増えるぶん、窓口の会話の圧縮は、早まります。

## 受け取った添付画像

通常のDiscord受信からCodexの会話へ、PNGとJPEGを画像入力として渡します。GIFは先頭の静止画像をPNGへ変換して渡します。動画としての内容や、2枚目以降のフレームは読みません。PDF、音声、動画、WebP、HEIC、アーカイブは、この経路ではまだ対応していません。未対応や取得失敗は本文に説明を添え、通常の依頼への対応を続けます。Claude Codeの入力経路では画像を取得せず、未対応であることを会話へ伝えます。

受信時は、従来と同じサーバー、チャンネル、投稿者の受け付けを通ったあとで、元のチャンネルID、メッセージID、投稿者ID、添付IDだけを依頼キューへ保存します。返信用スレッドを作った場合も、元の投稿の場所を使います。添付の期限付きURLは、依頼本文にもキューにも保存しません。本文中のURLは添付として取得しません。

実行時は、Bot認証で元のチャンネルとメッセージを取得し直し、サーバー、受け付け対象のチャンネル、投稿者、添付IDを照合します。Discordの添付URLは有効期限を持つため、順番待ちのあとで取得し直します。公式CDN `https://cdn.discordapp.com/attachments/<channel>/<attachment>/<filename>` だけを対象とし、CDNへはBot認証を渡しません。HTTPのリダイレクトは、メッセージ取得と画像取得の両方で止めます。取得エラーにURLや認証情報を含めません。

1件の依頼に複数の発言がまとまっている場合も、添付を調べるのは合わせて先頭の4件までです。1件の取得上限は 8 MiB で、画像は4000万画素までです。Discordのサイズと実際に取得したサイズ、画像としての形式と読み込み可否を確かめます。`content_type` がある場合は実際の形式との一致も確かめ、省略された場合は画像の中身で判定します。GIF を変換したあとの PNG にも 8 MiB の上限を適用します。

画像は、状態ファイルと同じ場所に作る `.incoming-images/turn-*` に一時保存します。権限はディレクトリーを 0700、ファイルを 0600 にします。利用者が付けたファイル名は保存先に使いません。Codexの `turn/start` へ絶対パスの `localImage` と本文を渡し、会話の応答が終わったとき、接続が切れたとき、処理が失敗したときに、同じ一時ディレクトリーを削除します。強制終了で残った `turn-*` は、次のBot起動時に削除します。画像そのものは Git や日ごとのログには保存しません。モデルの会話履歴の保管は、Codex側の設定に従います。

2026-11-24に、合成画像とHTTP・Codex通信のスタブで確認しました。実際の家庭用Discordの写真を使った認識精度と、本番のCodex app-serverへ画像が渡ることは、まだ確かめていません。

根拠は、[Discordの期限付き添付URLの説明](https://github.com/discord/discord-api-docs/blob/main/developers/reference.mdx#signed-attachment-cdn-urls)と、[Codex app-serverの入力の定義](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/turn.rs)です。2026-11-24に確認しました。

### 過去の投稿に付いた画像

Discordの利用者から依頼を受けたときは、その依頼を受けたチャンネルの過去の投稿を、メッセージIDで読み直せます。返信のために新しいスレッドを作った場合も、依頼が届いた場所を使います。既存のスレッドで受けた依頼の範囲は、そのスレッドです。届いた場所が記録されていない依頼、定例投稿、Webからの依頼には、この読み直しを案内しません。

Codexが過去の添付を確認する必要があると判断した場合は、専用の応答にメッセージIDを指定します。サーバーはその応答を投稿せず、Discordから最新の添付情報を取り直します。元の依頼と同じチャンネルであることと、投稿者が受け付けの範囲にいることを確認し、受信時と同じ画像の検査と一時保存を使います。添付URLとチャンネルの指定は受け付けません。取得できた画像は同じ会話の続きに画像入力として渡し、一時ファイルはそのターンの終了時に消します。

1回に4件まで、1つの依頼で2回まで読み直せます。取得できなかった場合は、画像を見たと答えず、分かった範囲で事情を伝えます。画像の形式と大きさの制限は、受信した画像と同じです。

## 招待先で投稿を読む

`DISCORD_MONITOR_ALL_CHANNELS=true` を設定すると、レイシアは、招待された Discord サーバーで、対応表に登録された方の投稿を読みます。対象は、Bot が投稿を読めるチャンネルと、参加中のスレッドです。ほかの Bot や Webhook による投稿、システムからのお知らせ、未登録の方の投稿は、会話に渡しません。再接続したときは、前に読んだところから続きを確かめます。初めて見つけたチャンネルでは、それ以前の投稿をきっかけに会話を始めることはありません。

レイシアのチャンネルと、そこでレイシアが作った会話用のスレッドでは、ふだんどおりに話します。ほかのチャンネルでも、メンションで呼ばれたら返事をします。直接呼ばれていないときは、別の会話で投稿を読み、参加者に返事や手助けが要るかを判断します。返事が必要だと判断し、投稿する文章を指定できたときだけ、元の場所へ届けます。判断に失敗したときは投稿しません。この判断をきっかけに、外部のサービスを操作したり、別の仕事を始めたりすることはありません。

前のやり取りが必要なときは、元の投稿を確かめてから、同じチャンネルかスレッドの履歴を読みます。読めるのは、元の投稿より前の履歴で、1ページ24件まで、最大3ページです。日付やメッセージの ID が分かれば、読み始める位置を指定できます。
