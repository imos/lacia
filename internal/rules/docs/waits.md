# 長くかかる計算を待つとき

クラスタなどへ計算を投げて、終わるのを待つときと、終わったという知らせを受けたときに読みます。

待ちの仕組みを使えるのは、サーバーが待ちを受け付け（設定の `waits` が有効）、端末の `lacia agent` が `kubectl` で対象を確かめられる導入先です。使うクラスタの名前と確かめ方は、導入先の決まりにあります。

## 待ちを登録する

- 計算を投げたら、会話を開いたまま待たずに、待ちを登録します。Job を投入するときは、`lacia job run --task <ID> --context <context> -f <YAML> --by <期限> "終わったらすること"` で、投入と登録を1度に行います。
- すでに動いている Job には、`lacia wait add --task <ID> --job <context>/<名前空間>/<Job名> --by <期限> "終わったらすること"` を使います。Pod の中の処理は、最後に終了の印となるファイルを書き、`--file <context>/<名前空間>/<Pod>:<パス>` で待ちます。ファイルの1行目が `fail` で始まると、失敗として扱われます。
- `--by` には、終わる見込みの期限を必ず書きます。`6h` のような長さか、`2026-11-19 06:00` のような日時です。
- 登録すると、タスクは外部待ち（`waiting`）になります。終わると、続きを行う側へ知らせが届きます。続きの宛先は `--next` で選びます。`local-codex` のような会話の名前、場所だけ、種類だけ、`none` を指定できます。省くと、登録した会話と同じ場所と種類になります。`none` では続きの会話を始めず、タスクを確認待ちへ出します。
- 知らせを受けた会話は、登録した会話の中身を知りません。「終わったらすること」に、読むもの、成果物の名前、許可の範囲を書きます。足りない前提は、対象のタスクの `notes.md` へ先に保存します。
- 見張りは、後処理を実行しません。集計や保存のような機械的な後処理は、ジョブ自身の最後の手順に入れます。判断の要る後処理は、続きの会話が行います。

## 知らせを受けたとき

- 続きの会話は、最初に `lacia wait ack <待ちか申し送りのID>` で受け取りを知らせます。そのあと、`lacia wait show <ID>` で内容を読みます。`ack` が、すでに受け取られたと返すときは、別の会話が進めているので何もしません。
- 待ちの知らせは、新しい許可ではありません。続きは、対象のタスクの `notes.md` の許可の範囲で行います。
- 待ちの期限を過ぎたときや、対象が見つからないときは、サーバーがタスクを確認待ち（`review`）へ出します。申し送りの受け取りが遅れたときや、開始の期限を過ぎたときは、タスクの状態を保ち、履歴と申し送りの一覧に残します。
- 待ちと申し送りの一覧は、`lacia wait list` で確かめます。要らなくなった待ちは、`lacia wait cancel <ID>` で取り消します。
