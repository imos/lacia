# 設定の一覧

`lacia serve` の引数、記録のリポジトリーに置く設定、環境変数を調べられます。機能ごとの詳しい説明は、それぞれの節から開けます。

## 設定の書き方

記録のリポジトリーで `lacia serve` を起動すると、既定の設定では `127.0.0.1` だけで待ち受けます。手元のブラウザーで `http://127.0.0.1:10148/` を開いてください。依頼の受付、Git へのプッシュ、Discord への接続は、それぞれ設定すると使えます。

設定を書くファイルは、2つあります。

- **端末の設定**（`~/.lacia/config/lacia.conf`）　その端末だけの設定です。記録の場所、会話に使うコマンド、待ち受けるアドレスのように、会話に書き換えさせたくない設定を書きます。`--config` を省くと、このファイルがあれば読みます。
- **記録の設定**（記録のリポジトリーの `.lacia/serve.conf`）　記録と一緒に持ち運ぶ設定です。表示名や夜の処理の時刻のような、記録の側に任せてよい設定だけを書けます。会話は記録へ書き込めるので、書ける項目を[限っています](#記録の側に置ける設定)。

同じ設定が複数の場所にあるときは、次の順で優先します。

1. コマンドラインの引数（`--addr 0.0.0.0:8080` など）
2. 端末の設定。`--config <ファイル>` を指定したときは、そのファイルです
3. 記録の設定（`.lacia/serve.conf`）
4. 下の表の既定

いまの値と、その値を決めた場所は、`lacia config` で一覧できます。`lacia serve` と同じ引数を渡すと、そのとおりに読みます。読むだけで、何も書き換えません。

ローカル環境で使い始めるときは、コマンドラインで `root` と、`codex` か `claude` を指定できます。別の環境でサーバーを動かす場合も指定は同じです。毎回使う設定は、端末の設定にまとめられます。 [ローカル環境で始める](../../README.md#ローカル環境で始める) · [別の環境で Web サーバーを動かす](../../README.md#別の環境で-web-サーバーを動かす)

### 道具の置き場所

本体は、自分のファイルを `~/.lacia` にまとめます。環境変数 `LACIA_HOME` を指定すると、その場所を使います。

| 場所 | 中身 |
| --- | --- |
| `~/.lacia/bin/` | 実行ファイル（`lacia`）と、1つ前の版（`lacia.previous`）です。`lacia setup` が置き、`~/.local/bin/lacia` からリンクで呼べるようにします（[導入と更新](install.md)） |
| `~/.lacia/config/lacia.conf` | 端末の設定です |
| `~/.lacia/config/logins.json` | このマシンのログインの一覧です（[ログインの違う Codex を呼び分ける](logins.md#このマシンのログインの一覧)） |
| `~/.lacia/state/` | サーバーの状態です。`state` を省いたときの既定です |
| `~/.lacia/logs/` | ログインのときに起動したサーバーのログ（`serve.log`）です。起動のときに 10 MiB を超えていたら、`serve.log.1` へ移します |
| `~/.lacia/config/google-client.json` | `lacia setup` に渡した、予定の連携に使う OAuth クライアントです |
| `~/.lacia/tmp/` | `lacia setup` が、リポジトリーの中身を確かめるときと、通知アプリを作るときに、一時的に使います |
| `~/.lacia/src` | 本体のソースです。クローンして入れた方だけにあります。別の場所にクローンした方は、そこへのリンクにします |

ホームの `~/.lacia/` と、記録の中の `.lacia/` は、同じ名前です。本体は、`.lacia/config.json` のある場所を記録とみなすので、`~/.lacia` の直下には `config.json` を置きません。

以前の版は、端末の設定を `~/.config/lacia/`（`XDG_CONFIG_HOME` があれば、その下の `lacia/`）に置いていました。ファイル名は `serve.conf` です。新しい場所にファイルがなく、古い場所にだけあるときは、古い場所のファイルを読みつづけます。そのうえで、ターミナルから実行したコマンドが、移すためのコマンドを1度だけ表示します。`lacia config` は、いつでも表示します。移すコマンドは、古いディレクトリーを新しい場所へ移し、古い場所には新しい場所へのリンクを残します。ログインのときにサーバーを起動する登録や、1つ前の版の実行ファイルが、古いパスでファイルを読みつづけられるようにするためです。会話は、ターミナルなしで `lacia` を実行するので、この知らせを受けません。

設定ファイルには、1行に「名前 = 値」の形で書きます。名前は、引数の名前から先頭の `--` を除いたものです。空の行と、`#` で始まる行は、読み飛ばします。次は、同じ機械で2つのプロファイルを組にする例です。パスは、サーバーを動かす環境で使う絶対パスに置き換えます。

```
codex = codex

[work]
label = 仕事
url = http://127.0.0.1:10148
addr = 127.0.0.1:10148
root = /path/to/records-work
state = /path/to/state/example-work
peer = home

[home]
label = 家庭
url = http://127.0.0.1:10149
addr = 127.0.0.1:10149
root = /path/to/records-home
state = /path/to/state/example-home
pages = false
peer = work
inbox = true
```

- `[名前]` の行から下は、そのプロファイルだけの指定です。それより上は、どのプロファイルにも当てはまります。
- 起動のときに、`--profile <名前>` で、どのプロファイルとして動くかを選びます。1つのプロセスが動かすのは、1つのプロファイルです。別々の環境で組にする場合は、それぞれが相手を呼べるアドレスを `url` に書きます。 [複数のプロファイル](profiles.md)
- `config` と `profile` は、設定のファイルの中には書けません。
- 実行ファイルが知らない名前は、ログに書いて読み飛ばします。1つ前の実行ファイルへ戻したときにも、新しい設定ファイルのまま起動できるようにするためです。どの設定も、書かれていないことで受け付ける範囲が広がることはありません。

プロファイルの名前に、コードは意味を持たせていません。何をするかは、指定の組み合わせで決まります。

## `lacia serve` の設定

次の表は `lacia serve --help` に出る引数の一覧です。表の中身は、本体のコード（`cmd/lacia/settings.go`）の表と同じです。食い違うと、テストが失敗します。表を直すときは、コードの表を直してから、`go test ./cmd/lacia -run TestSettingsDocumentFollowsTable -update` で、この文書の表を書き直します。

「書ける場所」の「端末」は、コマンドラインと端末の設定です。「記録」は、記録の設定（`.lacia/serve.conf`）にも書けることを表します。

### 基本

| 名前 | 既定 | 書ける場所 | 意味 |
| --- | --- | --- | --- |
| `config` | `~/.lacia/config/lacia.conf`（あれば） | コマンドライン | 端末の設定のファイルです。サーバーの設定を「名前 = 値」の形で1行ずつ書きます。[名前] で始まる節は、そのプロファイルだけに当てはまります |
| `profile` | なし | コマンドライン | 設定のファイルの中の、このサーバーが動かすプロファイルの名前です。共通の設定と同じ項目があれば、プロファイルの値を使います |
| `addr` | `127.0.0.1:10148` | 端末 | 待ち受けるアドレスです。ローカル環境で使うときは既定のまま、別の端末から使うときは接続できるアドレスを指定します |
| `root` | 自動で探します | 端末 | 記録のリポジトリーの場所です。~/ で始めて書けます。端末の設定の共通の部分に書くと、記録の外で実行したコマンド（lacia codex、lacia claude、lacia open など）も、この記録を使います。サーバーで省くと、環境変数 LACIA_TASKS を使い、それもなければ、いまのディレクトリーから親を順にたどって探します |
| `state` | `~/.lacia/state` | 端末 | 依頼の記録や、会話との接続の情報を置くディレクトリーです。記録のリポジトリーの外に置きます |
| `rescan` | `10s` | 端末 | ファイルの変更を取り込む間隔です。サーバーは同じ間隔で、タスクが待っている日時やほかのタスクの条件も確かめます |
| `site` | なし | 端末 | ブラウザーからこのサーバーに接続するための公開のアドレスです。予定の連携の戻り先と、外からの呼び出しの見分けに使います |
| `pages` | `true` | 端末 | false にすると、通常の画面と API を使えるのは、サーバーの手元からと、site のアドレスからです。プロファイル間のやり取りと稼働確認には、別の入口があります |
| `git-sync` | `false` | 端末 | 変更を Git へコミットして、プッシュします |
| `user` | オーナーさん | 端末 | わたしがオーナーさんを呼ぶ名前です（例: 田中さん）。省くと、環境変数 LACIA_USER、記録の .lacia/config.json の user の順に探します |
| `label` | `通常モード` | 端末、記録 | このプロファイルの呼び名です。画面、「わたしのこと」の文書、相手のプロファイルへの伝言に出ます |
| `people` | ほかの方 | 端末 | オーナーさんのほかに話す方々を、まとめて呼ぶときの名前です（例: ご家族）。伝言、引き継ぎ、自分についての記録の依頼の文面に出ます |

### 依頼と会話

詳しい説明は、[依頼の受付](requests.md)にあります。

| 名前 | 既定 | 書ける場所 | 意味 |
| --- | --- | --- | --- |
| `codex` | なし | 端末 | Codex を起動するコマンドです（例: codex-work）。指定すると、依頼を受け付けます |
| `codex-sandbox` | なし | 端末 | Codex のサンドボックスの設定です（例: danger-full-access） |
| `codex-model` | Codex の設定のまま | 端末 | Codex に使わせるモデルです。別のログインで起動する Codex（lacia codex-login）にも、同じモデルを渡します |
| `codex-effort` | Codex の設定のまま | 端末 | Codex の推論の強さです（例: medium） |
| `claude` | なし | 端末 | Claude Code を起動するコマンドです（例: claude）。指定すると、依頼を受け付けます。codex と一緒にも指定できます |
| `claude-model` | Claude Code の既定 | 端末 | Claude Code に使わせるモデルです |
| `claude-permission` | acceptEdits | 端末 | Claude Code の権限のモードです。既定の acceptEdits では、追加の許可がなくてもファイルを編集でき、シェルでは lacia コマンドが使えます |
| `default-kind` | Codex があれば codex | 端末 | 種類を省いた依頼や予約を渡す会話です。codex か claude を指定します |
| `places` | なし | 端末 | 別の端末で動かす場所と、その端末の登録名、既定の種類、秘密のファイルを、JSON で指定します |
| `instructions` | なし | 端末 | 会話への指示の文書です。指定すると、実行ファイルに入っている指示の代わりに使います |
| `instructions-extra` | なし | 端末、記録 | 会話への指示の最後に足す文書です。その環境だけに当てはまる決まりを書きます |
| `now` | `memory/now.md` | 端末、記録 | ふだんと違う状況を書いた文書の、記録のリポジトリーの中でのパスです。読めた内容を予約の依頼に添えます |
| `waits` | `true` | 端末 | クラスタの Job などの終了を、会話の外で待つ仕組みを使います |
| `routine-explicit-matters` | `false` | 端末 | 定期タスクでは、ご本人への用件が書かれた回だけ、受付を作ります |

`codex` も `claude` もないサーバーは、画面とタスクの読み書きだけを行います。依頼、予約、自分についての記録、伝言、Discord は、依頼を受け付けるサーバーでだけ動きます。

### 予定

詳しい説明は、[予定の連携](calendar.md)にあります。

| 名前 | 既定 | 書ける場所 | 意味 |
| --- | --- | --- | --- |
| `calendars` | 記録の `.lacia/calendars.json` | 端末、記録 | 表示して読むカレンダーの一覧です。JSON のファイルに account、calendar_id、label を書きます |
| `calendar-direct` | `true` | 端末 | サーバーが Google Calendar から予定を読みます。false にすると、これまでの予定のファイルを読みます |
| `google-client` | なし。Web の「予定の連携」のページで入力します | 端末、記録 | Google Calendar を読むための OAuth クライアントの JSON です。Google Cloud の「認証情報」でダウンロードしたファイルを指定します |
| `calendar-write` | `false` | 端末、記録 | 予定の連携で、読み取りに加えて、予定の作成や変更の許可も求めます。サーバーが自分から予定を書き換えることはありません |
| `calendar-holidays` | `jp` | 端末、記録 | 日本の祝日を表示するときは jp、表示しないときは off を指定します |
| `calendar` | 記録の `calendar/snapshot.json` | 端末、記録 | 予定のスナップショットのファイルです。以前の予約が作ったデータを取り込むときに使います |
| `calendar-overrides` | `.lacia/calendar-overrides.json` | 端末、記録 | 予定の表示の上書きを書いた JSON の、記録のリポジトリーの中でのパスです。ファイルがなければ、上書きはしません |

`calendar` の指定がないときは、記録のリポジトリーの `calendar/snapshot.json`、`results/calendar-web-snapshot.md` の順に探します。配信する版は、`<state>/calendar/snapshot.json` に保存します。`calendar` の指定と従来の場所は、以前の予約が作ったデータを取り込むときに使います。

### わたしのこと

詳しい説明は、[わたしのこと](self.md)にあります。

| 名前 | 既定 | 書ける場所 | 意味 |
| --- | --- | --- | --- |
| `self` | `memory/self.md` | 端末、記録 | 「わたしのこと」の文書の、記録のリポジトリーの中でのパスです。書き留めとページに使います。off にすると、夜の処理も、書き留めも、ページも止めます |
| `self-at` | 04:00。inbox のときは 03:30 | 端末、記録 | 夜の処理（夜の整理と、「わたしのこと」の書き直し）を毎日行う時刻です。記録のタイムゾーンで HH:MM と書きます。off にすると、夜の処理だけを止めます |
| `self-claude` | claude の設定の実行ファイル。なければ claude を探します | 端末 | 夜の処理に使う Claude Code の実行ファイルです。引数は付けられません。Claude Code も Codex も見つからない夜は、夜の処理を行わず、その理由を履歴に残します |
| `self-agent` | `auto` | 端末、記録 | 夜の処理を動かすものです。auto では、夜ごとに Claude Code を探し、見つからなければ Codex で動かします。claude か codex にすると、そちらだけで動かします。Codex では、codex の設定の実行ファイル（引数は使いません）と、codex-model、codex-effort を使います |
| `self-model` | `fable` | 端末、記録 | 夜の処理を Claude Code で動かすときのモデルです |
| `self-exchanges` | `true` | 端末、記録 | 夜の処理に、最近の依頼と返事（最長72時間分）を含め、記録のリポジトリーを読むことを許します。false のときも、前の版、書き留め、共有する節の変更は材料に残ります |
| `self-tidy` | `true` | 端末 | 夜の書き直しの前に、その日の話題と、memory/ に覚えておく候補を整理し、候補を窓口へ知らせます。self-exchanges が必要です。discord-log があれば、その日のログにも書きます |
| `self-improve` | `false` | 端末、記録 | 夜の書き直しで、「わたしのこと」の項目のうち、仕組みで直せそうなものを候補に挙げ、窓口へ知らせます。タスクを持つプロファイルでだけ動きます |
| `self-tidy-prompt` | なし | 端末 | 夜の整理の指示文です。指定すると、実行ファイルに入っている指示文の代わりに使います |
| `notice-log` | なし | 端末、記録 | 書き留めを日ごとに書き足すディレクトリーの、記録のリポジトリーの中でのパスです（例: log/notices）。discord-log と同じにすると、やり取りと同じファイルに入ります |

夜の処理（夜の整理と、「わたしのこと」の書き直し）は、依頼を受け付けるサーバーで、既定で毎日 04:00 に動きます。相手から伝言を受ける側（`inbox = true` と `peer` のあるプロファイル）の既定は 03:30 です。相手より先に書き直し、相手が、その夜のうちに共有する節を取り込めるようにするためです。夜の処理だけを止めるときは、記録の設定に `self-at = off` と書きます。書き留めと「レイシアのこと」のページも止めるときは、`self = off` と書きます。動かすものと、送る先は、[わたしのこと](self.md#夜の処理を動かすもの)にあります。

## 記録の側に置ける設定

記録のリポジトリーの `.lacia/serve.conf` で指定できるのは、次の16個です。

`label`、`instructions-extra`、`now`、`calendars`、`google-client`、`calendar-write`、`calendar-holidays`、`calendar`、`calendar-overrides`、`self`、`self-at`、`self-agent`、`self-model`、`self-exchanges`、`self-improve`、`notice-log`

ほかの名前は、ログに書いて読み飛ばします。理由は、[記録のリポジトリー](records.md#サーバーの設定のうち記録の側に置けるものlaciaserveconf)にあります。

`google-client`、`calendar`、`calendars`、`instructions-extra` に相対パスを書くと、記録のリポジトリーから数えます。`~/` は、ホームディレクトリーです。

## 記録の設定（`.lacia/config.json`）

| 項目 | 既定 | 中身 |
| --- | --- | --- |
| `format` | `0` | 記録の形式です。いまの `lacia` は形式2の記録だけを扱います |
| `areas` | `["work", "personal"]` | タスクを置く領域 |
| `area_labels` | なし | 領域の表示名 |
| `id_prefix` | `T` | 新しい ID の頭文字（英大文字1つ） |
| `user` | 「オーナーさん」 | オーナーさんの呼び名 |
| `reviewers` | なし | オーナーさんのほかに、確認を頼める人の名前 |
| `handoff_area` | 最初の領域 | 引き継がれたタスクを作る領域 |
| `calendar_hidden` | なし | 題名で表示から外す予定の規則（[予定の連携](calendar.md)） |
| `timezone` | `Asia/Tokyo` | 予約やタスクの日付、予定の取得と表示などに使う時間帯です。IANA の名前で指定します |

詳しい説明は、[記録のリポジトリー](records.md#記録の設定laciaconfigjson)にあります。

## 環境変数

| 名前 | 使う側 | 意味 |
| --- | --- | --- |
| `LACIA_TASKS` | コマンド | 記録のリポジトリーの場所 |

| `LACIA_HOME` | コマンド、サーバー | 道具の置き場所です。なければ `~/.lacia` です（[道具の置き場所](#道具の置き場所)） |

| `LACIA_ACTOR` | コマンド | 履歴に書く、書き込んだ人の名前 |
| `LACIA_PROFILE` | コマンド | 会話が動いている場所の名前です。サーバーのプロファイル名か、登録した端末の場所を使います。なければ `local` です。 [会話の名前と担当](waits.md#会話の名前と担当) |
