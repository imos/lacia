# 設計の文書

`lacia` の仕組みと、その設計を選んだ理由をまとめています。実装していない機能や、まだ動作を確かめていない箇所は、各文書に明記します。説明と実装に食い違いがあれば、コードを基準にしてください。

コマンドでは `lacia docs` でこの一覧、`lacia docs records` のようにファイル名から `.md` を外して指定すると各文書を読めます。Webでは画面下部の「設計の文書」から一覧を開けます。コマンドとWebはそれぞれの実行ファイルに入っている版を表示します。

## 読む順

使い始めるときは、[ローカル環境で始める](../../README.md#ローカル環境で始める)か、[別の環境で Web サーバーを動かす](../../README.md#別の環境で-web-サーバーを動かす)のうち、お使いの環境に合う手順を選んでください。仕組みを知りたい方には、次の順番をおすすめします。

1. [全体の構成](overview.md)で、サーバーと会話がそれぞれ何を受け持つかを確かめます。
2. [記録のリポジトリー](records.md)で、タスクの書き方と保存先を確かめます。
3. [決まりと会話の起動](rules.md)では、起動時にどの決まりが会話に渡るかを説明しています。
4. [依頼の受付](requests.md)では、受け付けた依頼が会話に届くまでをたどれます。

そのあとは、使う機能の文書を読んでください。設定の名前から探すときは、[設定の一覧](settings.md)が入口になります。

## この文書の書き方

- 書くのは、いまの設計です。変更の経緯や、検討の履歴は、書きません。経緯は、コミットとプルリクエストに残っています。
- 特定の人や環境の値（名前、アドレス、アカウント）は、書きません。例には、`example.com` や「田中さん」を使います。
- 記録のリポジトリーの持ち主を役割で指すときは「オーナーさん」と書きます。人の呼び名や担当する会話との区別は、[言葉の使い分け](terms.md)にあります。
- 文章は、[文章の書き方](writing.md)に従います。
