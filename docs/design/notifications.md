# Mac の通知

macOS 専用の通知アプリがメニューバーに常駐し、確認待ちや完了確認待ちになったタスクと、会議の開始を知らせます。アプリの裏では `lacia agent` が動いていて、サーバーから情報を読み、通知の予定を作ります。この文書では、2つの役割、インストール、対象と除外の設定を説明します。

macOS の端末で通知アプリとサーバーを一緒に動かすときは、アプリを同じ環境の `lacia serve` につなぎます。別の環境でサーバーを動かすときは、そのアドレスを指定します。読み取り専用のコピーを指定すると `lacia agent` が最新に保ち、Mac を受け取り先として登録すると、申し送りと予約も受け取れます。

## 2つの部品

| 部品 | 場所 | 役割 |
| --- | --- | --- |
| 通知アプリ | `macos/notifier/LaciaNotifier.swift` | メニューバーに常駐します。macOS へ通知を予約し、`lacia agent` を起動して見張ります |
| `lacia agent` | `cmd/lacia/agent.go`、`internal/notify/`、`internal/agent/` | 30秒ごとにサーバーからタスクと予定を読み、通知の一覧を作ります。別の機械から届く申し送りと予約も扱います |

役割を分けているのは、macOS の通知の許可がアプリに付くためです。通知の中身を決める処理は `lacia` の側に置いて、サーバーと同じコードで試験できるようにしています。

`lacia agent` は、通知の一覧を `manifest.json` に書きます。アプリは、それを読んで、macOS の予約と照らし合わせます。

メニューバーのアイコンのメニューの「レイシアを開く」で、ブラウザーに Web のホームの画面を開けます。開く先は、通知を押したときと同じ `site` のアドレスです。

## インストール

ふつうは、`lacia setup --notifier` で入れます。実行ファイルに入っている、同じ版のソースから作ります。`lacia setup` が実行ファイルを置き換えたときは、入っている通知アプリも作り直します。`lacia uninstall` は、`manage.py uninstall --remove-state` で、アプリと設定と状態を消します（[導入と更新](install.md#通知アプリ)）。ここからは、`manage.py` を直接使う方法です。

コードのリポジトリーで `macos/notifier/manage.py` を使い、アプリを作って入れます。管理者の権限は要りません。次の例は、同じ Mac で `lacia serve` を既定のアドレスで動かす場合です。先にサーバーを起動します。 [ローカル環境で始める](../../README.md#ローカル環境で始める)

```sh
mkdir -p build
python3 macos/notifier/manage.py build build/LaciaNotifications.app
python3 macos/notifier/manage.py install build/LaciaNotifications.app --lacia "$HOME/bin/lacia"
python3 macos/notifier/manage.py start
```

| サブコマンド | すること |
| --- | --- |
| `build <出力先>` | Swift のコードからアプリを作って、署名します |
| `upgrade <アプリ>` | 入れてあるアプリを、新しく作ったものへ入れ替えて、起動し直します。設定と、予約済みの通知は、そのままです |
| `install <アプリ>` | アプリ、設定、LaunchAgent を置きます。起動はしません |
| `start` | LaunchAgent を登録して、起動します |
| `stop` | 止めて、macOS に予約済みの通知をすべて消します |
| `uninstall` | 予約を消して、アプリと LaunchAgent を消します。設定と状態のディレクトリーは残します。`--remove-state` を付けると、それも消します |

置く場所は、次のとおりです。

| もの | 場所 |
| --- | --- |
| アプリ | `~/Applications/Lacia Notifications.app` |
| 設定と状態 | `~/Library/Application Support/Lacia Notifications/` |
| LaunchAgent | `~/Library/LaunchAgents/jp.imoz.lacia.notifications.plist` |

`install` は、アプリ、設定、LaunchAgent のどれかがすでにあると、何も変えずに止まります。入れてあるものを新しくするには `upgrade` を使います。

### 通知のアイコン

通知のバナーには、アプリのアイコンが出ます。macOS 26 は、外形が標準の角丸の四角でないアイコンを、灰色の台に載せて小さく表示します。`brand.png` の絵柄は円形なので、そのまま使うと、バナーの絵柄が小さくなり、外側に灰色の枠が出ます。

そこで `build` は、`render-icon.swift` で、通知アプリのアイコンだけを別に描きます。1024 px の画面に、標準の角丸の四角（824 px）を、淡い紫で塗り、その中に円形の絵柄をいっぱいの大きさで置きます。メニューバーと Web では、`brand.png` をそのまま使います。

アイコンのファイル名には、元の画像と描き方から作ったハッシュを入れます。macOS がアイコンを古いまま持ち続けないようにするためです。それでも、通知センターは、動いているあいだ、読んだアイコンを覚えています。`upgrade` のあとにバナーのアイコンが変わらないときは、`killall NotificationCenter` で通知センターを起動し直します。macOS がすぐに起動し直します。

### 接続先を決める引数

`install` の引数で、どのサーバーへつなぐかを決めます。

| 引数 | 意味 |
| --- | --- |
| `--lacia <場所>` | アプリが裏で動かす `lacia` の実行ファイルです。省くと、インストール時の `PATH` で探します |
| `--url <アドレス>` | サーバーのアドレスです（例：`http://127.0.0.1:10148`） |
| `--site <アドレス>` | 通知から開くページのアドレスです。省くと、`--url` と同じになります |
| `--context`、`--namespace` | サーバーが Kubernetes のクラスタの中で動いているときの、`kubectl` の context と名前空間です。2つそろえて指定します |
| `--target` | `kubectl port-forward` でつなぐ先です（例：`service/lacia`）。`--context` と一緒に、必ず指定します |
| `--port` | port-forward の手元のポートです。既定は `18190` です |
| `--remote-port` | つなぐ先のポートです。`--context` と一緒に、必ず指定します |
| `--tasks-repo <場所>` | 記録のリポジトリーの、読み取り専用のコピーです。別の環境から記録を取り込むときや、Mac を予約や申し送りの受け取り先にするときに指定します |

同じ Mac で既定のアドレスを使うときは、接続の引数を省けます。別の環境へ接続する場合は、直接つなぐか、許可された転送を使います。

- **何も指定しない**：手元のサーバー（`http://127.0.0.1:10148`）へ、直接つなぎます。これが既定です。
- **`--url` を指定する**：指定したアドレスへつなぎます。同じ Mac で待ち受けポートを変えた場合や、別の環境へ HTTPS や許可された転送で接続する場合に使います。
- **`--context` と `--namespace` を指定する**：`lacia agent` が `kubectl port-forward` を保って、クラスタの中のサーバーへつなぎます。転送先とブラウザーで開く URL が異なる場合は、`--site` でブラウザー用のアドレスを指定します。

`--url` と、クラスタ用の引数は、同時には指定できません。

`--lacia` を省くと、`PATH` にある `lacia` を使います。見つからなければ、入れずに止まります。

通知だけを使う場合は、どちらの構成でも `--tasks-repo` を省けます。指定する場合は、プッシュを止めたコピーを用意してください。 [読み取り専用のコピー](records.md#読み取り専用のコピー)

### 予約も受け取るとき

ローカル環境のサーバー自身で実行する予約は、`lacia serve` が動かします。macOS の通知アプリを同じ環境で使うときは、アプリがサーバーの結果を読みます。別の環境にあるサーバーから予約や申し送りを受け取る Mac では、その Mac が会話を起動できるように、記録のコピー、場所の名前、端末の登録名を指定します。

```sh
python3 macos/notifier/manage.py install build/LaciaNotifications.app \
  --lacia "$HOME/bin/lacia" --url https://records.example.com \
  --tasks-repo "$HOME/records-copy" --place local --schedule-device desk-device
```

インストールすると、アプリの設定ディレクトリーに秘密のファイル `schedule-device.secret` を作ります。すでに秘密を用意した場合は、`--schedule-secret-file <ファイル>` で指定できます。同じ秘密を、サーバーの設定に書いた `secret_file` にも安全な経路で置きます。[サーバーに場所を登録する](schedules.md#サーバーに場所を登録する)

別の常駐プログラムで予約を受け取っていた Mac を切り替えるときは、`upgrade <アプリ> --migrate-schedule` を使います。以前の登録情報と実行回の記録を引き継ぎます。サーバーの場所設定と予約の `to` も、同じ切り替えに合わせます。Claude の起動コマンドを個別に設定していたときは、使うコマンドを `logins.json` のログインの `claude` へ移します。申し送りに要る `-p` は、実行するときに付きます。[ログインの一覧](logins.md#このマシンのログインの一覧)

## 設定（`config.json`）

設定は、`~/Library/Application Support/Lacia Notifications/config.json` にあります。`install` が作ります。`lacia agent` は、通知の設定を定期的に読み直します。接続先や端末登録を変えたら、`lacia agent` を起動し直してください。

```json
{
  "enabled": true,
  "task_notifications": true,
  "meeting_notifications": true,
  "meeting_source": "linked",
  "exclude_meetings": [],
  "lacia": "/Users/example/bin/lacia"
}
```

| 項目 | 意味 |
| --- | --- |
| `enabled` | `false` にすると、通知を出しません |
| `task_notifications`、`meeting_notifications` | タスクの通知と、会議の知らせを、それぞれ出すかどうかです |
| `meeting_source` | `linked` と書きます。サーバーが読んだ予定を使う、という意味です |
| `exclude_meetings` | 知らせない会議の規則です（下の「会議の知らせ」） |
| `lacia` | アプリが裏で動かす `lacia` の場所です。アプリは、`lacia agent` として起動します |
| `site` | 通知から開くページのアドレスです。なければ `transport.url`、それもなければ `http://127.0.0.1:10148` です |
| `transport` | サーバーへのつなぎ方です。`url` か、`kubectl`、`context`、`namespace`、`port`、`target`、`remote_port` を書きます。なければ、手元のサーバーへつなぎます |
| `tasks_repo` | 読み取り専用のコピーの場所です |
| `place` | この Mac で申し送りを受けるときの、サーバーに登録した場所の名前です。省くと `local` です |
| `schedule` | 別のサーバーから予約や申し送りを受け取るときの端末登録です。インストール時に設定します |

`enabled`、`meeting_notifications`、`meeting_source`、`exclude_meetings`、`lacia` は、省けません。どれかが欠けると、アプリは設定を読めず、何もしません。

通知から開くのは、`site` と同じアドレスのページだけです。`http` を認めるのは、`127.0.0.1` と `localhost` だけです。ほかは `https` にします。

## タスクの通知

タスクが確認待ち（`review`）になったときに、「確認をお願いします」と知らせます。完了確認待ち（`closing`）になったときは、「作業が終わりました」と知らせます。通知を押すと、そのタスクのページを開きます。

- 起動して最初に読んだ時点で、すでに確認待ちか完了確認待ちだったタスクは、知らせません。そのあとにその状態になったものを知らせます。
- すでに確認待ちのタスクでも、書き込みを止めた時刻（`stopped_at`）が新しくなると、アプリは「繰り返しの書き込みを止めました」と知らせます。サーバーは、同じ呼び出し元から同じタスクへの書き込みを数えます。30分のあいだに同じ内容が10回届くか、内容を問わず合計1000回に達すると、その呼び出し元からそのタスクへの書き込みを30分間止めます。対象の操作は[安全のための仕組み](safety.md#同じ書き込みの繰り返しを止める)にあります。
- 完了確認待ちのタスクが確認待ちへ移ったときは、新しい用件として「確認をお願いします」と知らせます。確認待ちのタスクを完了確認待ちへ移しただけのときは、知らせません。
- 確認待ちでも完了確認待ちでもなくなったタスクの、まだ出していない通知は、取り消します。

## 会議の知らせ

会議の開始の1分前に知らせる予定を、アプリの手元に24時間先まで登録します。開始10分前と1分前には、サーバーへGoogle Calendarの再取得を求めます。取り消しや時刻の移動を確認できたときは、元の通知を止めます。会議の予定が今も有効か確かめられないときは、すでに登録した時刻に知らせます。Mac が眠っている場合は復帰時に見直し、会議がすでに始まっていれば知らせません。

通知を押すと、Google Calendar でその回の予定を開きます。カレンダーから取得した予定のリンクを使います。リンクが取得できなかった場合は、レイシアのホームを開きます。

### 対象

対象のカレンダーは、サーバーの設定（`calendars`）の一覧と同じです。`lacia agent` が、サーバーの `GET /api/calendar/scope` から受け取ります。Mac の側で、カレンダーを指定する必要はありません。

本人の回答が、未回答、承諾、仮承諾のどれであっても、知らせます。未回答のままであることから、不参加だとは判断しません。

次の予定は、知らせません。

- 終日の予定
- 取り消された予定と、本人が辞退した予定
- 種類が通常の予定でないもの（勤務場所、不在、集中する時間など）
- [表示の上書き](calendar.md#表示の上書きcalendar-overrides)を付けた予定

会議と判定する根拠は、次のどちらかです。

- 本人と設備のほかに、参加者がいます。
- 会議のサービスのアドレスがあります。確かめるのは、Google Meet（`meet.google.com`）、Zoom（`zoom.us`）、Microsoft Teams（`teams.microsoft.com`）のホスト名です。場所の欄と説明文の中のアドレスも見ます。

どちらもない予定は、会議かどうかが「不明」になります。不明の予定には、新しい通知を作りません。その予定にすでに通知があれば、そのまま保ちます。

### 除外（`exclude_meetings`）

知らせなくてよい会議は、設定の `exclude_meetings` に規則を書いて外します。

```json
"exclude_meetings": [
  {"account": "tanaka@example.com", "calendar_id": "primary", "title_contains": "朝会"},
  {"event_id": "（1回だけ外す予定の ID）"}
]
```

- 使える項目は、`account`、`calendar_id`、`event_id`、`title_contains` の4つです。
- 1つの規則に書いた項目は、すべて一致する必要があります。どれか1つの規則に一致した予定を、外します。
- `title_contains` は、文字列の部分一致です。正規表現ではありません。大文字と小文字を区別します。
- 空の規則や、知らない項目のある規則があると、予定を取得できなかったものとして扱います。すでにある予約は、消さずに保ちます。

同じ予定をホームの予定欄からも外したいときは、記録の `calendar_hidden` にも題名の規則を書きます。[決まった題名の予定を出さない規則](calendar.md#決まった題名の予定を出さない規則)

### 取得できなかったとき

予定の取得に失敗したとき、一部しか取れなかったとき、予定が古いとき（取得から35分を過ぎたとき）は、それを「予定が消えた」証拠としては扱いません。すでにある予約を保ちます。会議開始前であれば、Macの復帰時に知らせます。会議が始まったあとは知らせません。

サーバーと通信できなかった場合も、会議とタスクの予約を保ちます。通信が戻ってから、取得した予約の一覧で照合します。

取り消しの確認は、`POST /api/calendar/refresh` で直接取得を求めてから、保存された一覧で行います。確認する時刻と結果は `worker.log` に残します。1分前の取得中は最大35秒待ち、結果が届かなければ事前の計画で知らせます。通信が切れているときとアプリを起動し直したときも、`meeting-plan.json` に保存した計画から知らせます。開始時刻が変わった予定には新しい識別子が付き、新しい時刻で再び確認します。取得に失敗した予定や古い予定だけを理由に、通知を止めることはありません。

サーバーではカレンダーごとの取得成功時刻を、Macでは受け取った全体とカレンダーごとの時刻をログに残します。通知計画の `calendar=partial` には会議か判定できない予定がある場合も含むため、Googleからの取得が失敗したかどうかは、スナップショットの各sourceの状態で確かめます。

## macOS の予約との照合

macOS が通知の予約を落とすことがあるので、アプリは、出すべき通知と、macOS が実際に持っている予約を、照らし合わせます。

照合するのは、次のときです。

- 起動した直後
- 通知の予定が変わったとき
- 前に照合が成功してから、3時間たったとき（スリープから復帰したときにも、時刻を確かめます）

照合では、次のことを行います。

- 通知時刻が来た会議を最新の一覧で確認し、まだ知らせていなければ表示します。
- 題名、本文、開く先、時刻が違う予約は、正しい内容に置き換えます。
- 取り消された予定は、macOS の予約一覧と、アプリが以前登録した通知の台帳の両方から識別子を見つけて取り消します。元の通知時刻の翌日まで、アプリの再起動をまたいで取り消しを再要求します。すでに配信済みになった対象の通知も、通知センターの一覧から取り除きます。
- 登録したあとに、macOS の一覧を読み戻して確かめます。

状態のディレクトリーには、次のファイルができます。

| ファイル | 書く側 | 中身 |
| --- | --- | --- |
| `agent-state.json` | `lacia agent` | タスクの基準、会議の通知、同期の状態 |
| `meeting-plan.json` | 通知アプリ | 通信障害と再起動をまたいで保つ会議の計画 |
| `manifest.json` | `lacia agent` | 出すべき通知の一覧と、取得の状態 |
| `accepted.json` | アプリ | macOS が受け付けた通知の台帳 |
| `cancelled-meetings.json` | アプリ | 取り消した会議通知の識別子と、元の通知時刻 |
| `reconciliation.json` | アプリ | 照合の最新の結果 |
| `reconciliation.log` | アプリ | 照合の履歴です。追記する前に大きさを調べ、2 MiB を超えていれば新しいファイルに書きます |
| `worker.log` | `lacia agent` | 動作の記録 |

照合の記録には、件数と時刻だけを書きます。予定の題名と、会議のアドレスは、書きません。

アプリの実行ファイルには、確かめるための引数があります。

| 引数 | すること |
| --- | --- |
| `--audit-pending` | 予約の件数だけを表示します |
| `--status` | 通知の許可の状態を表示します |
| `--test` | 試しの通知を1件出します |
| `--self-test` | アプリの中の判定を試験します |
| `--clear-pending` | 予約をすべて消します |

照合の記録と `--audit-pending` で分かるのは、macOS に予約があることまでです。通知が画面に出たかどうかは、分かりません。集中モードや、Mac がその時刻に起きていたかどうかは、別に確かめる必要があります。

## 記録のコピーを最新にする

`tasks_repo` を指定すると、`lacia agent` が、読み取り専用のコピーへ、サーバーのコミットを取り込みます。

- サーバーは、タスクの一覧の応答に、プッシュ済みのコミットを添えます。`lacia agent` は、コミットが変わったときに取り込みます。
- 取り込むのは、コピーのプッシュの宛先が `disabled://lacia-local-readonly` になっていて、`main` のブランチにいて、ほかの Git の操作が進んでいないときです。
- 取り込みとぶつかる手元の変更は、消さずに、`local/mirror-recovery/` へ退避します。退避があると、メニューバーに「退避した変更（要確認）」が出て、選ぶと Finder で開きます。
- 手元の履歴がサーバーの履歴と分かれているときは、取り込まずに止めます。
- 同期が15分より長く止まると、1度だけ通知します。メニューバーのいちばん上で、同期の状態を確かめられます。

[終了を待つ仕事](waits.md)の見張りも、`tasks_repo` を指定したときだけ動きます。

## まだ整っていないこと

- 何も入っていない Mac での、インストールから通知が出るまでの通しの確認は、まだ行っていません。
- アプリの識別子（`jp.imoz.lacia.notifications`）は、開発者の識別子です。変えると、通知の許可を取り直すことになるので、このままにしています。
