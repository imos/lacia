# わたしのこと

「わたしのこと」（`memory/self.md`）は、やり取りを重ねるなかで気づいたことや、自分の好みを、レイシアが一人称で書く短い文書です。昼には心に残ったことを書き留め、夜には前の版を読み返して、少しずつ書き直します。

## 考え方

自分についての記録を読み書きするときは、決まりや記憶と区別します。

| もの | 中身 | 扱い方 |
| --- | --- | --- |
| 決まり | オーナーさんが定めたこと。口調、許可の範囲など | レイシアは会話の始めと、会話が圧縮されたあとに読み直し、同じ決まりに従います |
| 記憶 | 言われたことと、起きたこと。`memory/` の文書や、タスクの履歴 | 日付と一緒に、そのまま残します |
| 自分についての記録 | レイシアの受け止め方。`memory/self.md` | 書き直しで、ゆっくり変わります |

- 相手が何を大事にしているように感じたか、自分は何が気になったかを、確かに言える範囲で書きます。気に入ったもの、苦手なもの、心に残ったやり取り、してみたいことも書けます。
- 自分についての記録を読み返すと、以前に気になったことを尋ねたり、意見が違うときにその理由を伝えたりできます。
- 気持ちを書くときは、何があってそう感じたのかを、その日の書き留めややり取りからたどります。1度気に入っただけで、自分の好みが決まったとは書きません。人柄の説明は、[口調と人柄](voice.md)にあります。
- 自分についての記録は、許可や権限を変えません。決まりと食い違うときは、決まりに従います。
- 自分についての記録の行数には上限があります。新しく気づいたことを書くときには、重なる記述をまとめ、いまの見方に合わなくなった文などを必要に応じて省きます。覚えておくべき事実は、記憶の文書に残します。

## 昼は、書き留めるだけ

ローカル環境で使う場合も、別の環境で使う場合も、書き留めと夜の書き直しは、自分についての記録を設定したサーバーが扱います。複数のプロファイルで共有する設定は、記録を分けて運用するときに使います。

窓口の会話は、心が動いたことを、1〜2行だけ書き留めます。

```
lacia notice [--task ID] "（文章）"
```

- 予想と違う反応があったとき、おすすめが通らなかったとき、自分の判断に悔いが残ったとき、相手が大事にしていることが見えたときに書きます。うれしかったこと、おもしろかったこと、好きだと思ったことも書きます。事実の写しではなく、受け止め方を書きます。
- 自分についての記録の本体には、触れません。そのつど本体を直すと、直前の1件に引きずられて、振れすぎるためです。
- 書き留めは、1件が1000字までです。`state` のディレクトリーの `self/notes.jsonl` に置きます。Git には入りません。
- 設定の `notice-log` を指定すると、書き留めの写しを、記録のリポジトリーの日ごとのファイルにも書き足します。こちらは消えません。

`lacia self` は、いまの記録と、次の書き直しに使う書き留めを表示します。採用を見送った夜があれば、それ以前の書き留めも残っています。

## 夜に振り返り、全体を書き直す

`self-at` の時刻になると、サーバーはプロファイルごとに、窓口とは別の Claude Code セッションをその夜だけ開きます。まず、その日の出来事を夜の整理で確かめます。次に、同じセッションの別のターンで「わたしのこと」を書き直します。

1. サーバーは、整理するやり取りを渡し、話題と記憶の候補を受け取って点検します。整理結果の保存先と窓口への通知は、[夜の整理](#夜の整理)にまとめています。
2. サーバーは前の版と書き留めを渡し、その日の出来事をどう受け止めたかを考えるよう頼みます。`self-exchanges` が有効なら、返事まで済んだ人からの依頼も、前回の処理以降から最長72時間分を材料にします。書き留めややり取りに加えて、記録リポジトリーの更新も書き直しを始める手がかりになります。
3. モデルは「わたしのこと」の全文と、「今夜変えたこと」の短い説明を返します。サーバーの点検に通らなければ、理由と最初の案を添えて、書き直しだけを1度やり直します。やり直した案も通らなければ、前の版と書き留めを次の夜に持ち越します。
4. 採用したらサーバーが文書を保存し、書き直しを始めるまでに受け取った書き留めを消します。窓口には新しい版を読み直すよう知らせます。

Claude Code はそのプロファイルの記録リポジトリーから起動し、必要なファイルを検索して読めます。ファイルを編集する道具、シェル、外部コネクターは無効です。作業用のディレクトリーや認証設定は読み取りから外し、リポジトリーに書かれた指示やフックは自動で読み込みません。`self-exchanges = false` のときはファイルの読み取りも無効にします。

日曜日に書き直すときは、7日ほど前の版があれば一緒に渡します。モデルは過去の版と今夜の材料を読んで、この1週間で見方が変わった箇所を確かめます。この回だけ、変えてよい文の数を増やします。

### 点検

次のどれかに当たる案は、採用しません。

- 題名か見出しが決まった形から外れています。文書は `# わたしのこと` で始まり、`## わたし自身` と `## <プロファイルの呼び名>で` の節が要ります。
- 長さが上限を超えています。空行を除いて120行まで、全体で14400字までです。
- 1晩で変えた文が、下の表の上限を超えています。

「変わりすぎ」は、文の単位で数えます。箇条書きの1項目を「。」で文に分けて、前の版と比べます。

| | なくなった文 | 新しく加わった文 |
| --- | --- | --- |
| ふだんの夜 | 前の版の文の4割まで | 前の版の文の数の4割まで |
| 日曜日 | 7割まで | 6割まで |
| 割合にかかわらず認める数 | 12文まで | 36文まで |

文の単位で数えるのは、項目が長くなっても、1文を足しただけの変更を、項目全体の変更として数えないためです。モデルには、変えない文を、一字一句そのまま残すように頼んでいます。前の版の文の数と、今夜なくしてよい文の数、足してよい文の数も、あらかじめ伝えます。前の版がない最初の夜は、この点検をしません。

### 採用しなかった案

採用しなかった案は、捨てずに残します。やり直した夜は、やり直したあとの案を残します。`state` のディレクトリーの `self/rejected/<日付>.md` に置き、Web の「レイシアのこと」のページの、夜ごとの記録から読めます。なぜ採用されなかったのかを、あとから確かめられるようにするためです。Git には入りません。

モデルの呼び出しそのものが失敗した夜は、案がないので、理由だけを記録します。

### 時刻

- 設定の `self-at` に、毎日書き直す時刻（記録の `timezone`。既定は `Asia/Tokyo`）を書きます。指定がなければ、自動では書き直しません。
- その時刻にサーバーが動いていなかった日は、動きはじめたときに書き直します。何日か動いていなかったときも、繰り返さずに、1回にまとめます。
- 採用されなかった夜も、同じ日には繰り返しません。
- `lacia self sleep` で、その場で書き直しを始められます。材料がなくても試すときは、`--force` を付けます。

### 置き場所

| もの | 場所 | Git |
| --- | --- | --- |
| 自分についての記録 | 記録のリポジトリーの、設定の `self` の場所（ふつうは `memory/self.md`） | 入ります。変わり方が履歴に残ります |
| 書き留め | `state` の `self/notes.jsonl` | 入りません。採用した夜に消えます |
| 書き留めの写し | 記録のリポジトリーの、設定の `notice-log` の場所の下の `<年月>/<日付>.md` | 入ります |
| 夜ごとの記録 | `state` の `self/history.jsonl` | 入りません |
| 夜ごとの版 | `state` の `self/versions/<日付>.md` | 入りません |
| 採用しなかった案 | `state` の `self/rejected/<日付>.md` | 入りません |

## 「レイシアのこと」のページ

Web の「レイシアのこと」（`/self`）では、いまの版、書き直しに使う書き留め、夜ごとの記録を読めます。保存する文書の題「わたしのこと」と共有節「わたし自身」は、画面で読むときだけ「レイシアのこと」「レイシア自身」と表示します。JSON API と保存内容の見出しは変えません。夜ごとの記録には、採用したかどうか、変えたこと、採用しなかった理由が並びます。

オーナーさんがレイシアの記録を直したいときは、文書を書き換えるのではなく、このページからひとこと伝えます。サーバーはその言葉をオーナーさんからの書き留めとして保存し、次の書き直しの材料に加えます。

サーバーに公開のアドレス（`site`）を設定しているときは、公開のアドレスを通った画面からだけ、ひとことを伝えられます。会話が、オーナーさんの言葉として書き込めないようにするためです。`site` を設定していないサーバーでは、この区別はありません。

## 外へ送られるもの

夜の整理や書き直しを頼むと、サーバーは Claude Code を通して、その回に使う材料をモデルの提供元へ送ります。Claude Code が検索や読み取りで取得した内容も送られます。

- やり取りは、依頼と返事を、それぞれ1200字で切ります。全体は、新しいものから、約6万字までです。
- 依頼と返事を送りたくないときは、`self-exchanges = false` にします。この設定でも、前の版と書き留めはモデルへ渡します。「わたし自身」の節を共有していれば相手から届いた変更を、日曜日なら手元にある過去の版も渡します。

## 複数のプロファイルで共有する

自分についての記録には「わたし自身」（`## わたし自身`）の節があります。2つのプロファイルを[組にしている](profiles.md)とき、この節だけを共有します。どちらのプロファイルで話しても、同じレイシアであるようにするためです。ほかの節（`## <プロファイルの呼び名>で`）は、それぞれのプロファイルのものです。

「わたし自身」の節には、「ものの見方」「好きなこと、苦手なこと」「心に残っていること」「してみたいこと」の4つの小見出しを置きます。好きなものや心に残ったことは、だれと話すときにも思い出せるよう、「わたし自身」の節に書きます。一緒にいる方それぞれについて感じたことや、その場で気づいた自分の癖は、プロファイルごとの節に書きます。

共有は、伝言を送る側（`inbox` のないほう）が、受ける側（`inbox = true` のほう）を呼ぶ向きで行います。

1. 受ける側が、先に、自分の材料で書き直します。共有する節も、そちらでのやり取りに合わせて変わります。
2. 送る側が、そのあとで書き直します。始める前に、受ける側のサーバーの `GET /api/self/core` で共有する節を読みます。手元の共有節と違えば、材料に加えます。モデルが、2つを1つにまとめます。
3. 送る側のサーバーが、まとめた節の本文を `PUT /api/self/core` で渡します。受ける側のサーバーは、「わたし自身」の節だけを置き換えて、窓口へ知らせます。

この順になるように、受ける側の `self-at` を、送る側より早い時刻にします。

- 相手のサーバーへつながらない夜は、手元の共有節のまま書き直して、夜ごとの記録に、そのことを残します。次の夜に、まとめ直します。
- 相手のプロファイルへ送るのは共有する節の文章だけです。書き留めとやり取りは、プロファイル間で共有しません。
- 「わたし自身」の節に書かないことは、モデルへの依頼の文章（`internal/self/prompt.md`）で決めています。仕事の中身と、オーナーさん個人のお金、医療、メールのことは、「わたし自身」の節に書きません。まわりの方の発言そのものは、どの節にも写しません。書くのは、レイシアの受け止め方です。
- 夜の書き直しでは、オーナーさんのほかにレイシアが話す方々の目にも触れうるものとして、共有する節を書くよう伝えます。その方々の呼び方は、設定の `people` から取ります。

## 夜の整理

夜の整理では、あとで「いつ何を話したか」を探せるようにし、長く覚えておくとよい事実や好みを候補にします。仕事側でも家庭側でも、夜の書き直しが有効で、`self-exchanges` と `self-tidy` が有効なら動きます。

整理の指示文は、実行ファイルに入っています（`internal/self/tidy.md`）。仕事側と家庭側の両方で、同じ指示文を使えるように書いています。家族と共有する記録で仕事の中身を候補にしないことも、この指示文に入っています。それでも環境に合わせて丸ごと変えたいときは、`self-tidy-prompt` で指示文を指定できます。差し替えた指示文は、実行ファイルの指示文が変わっても追いつかないので、なるべく使いません。`{{呼び名}}`、`{{OTHERS}}`、`{{MODE}}`、`{{FILES}}`、`{{DATE}}`、`{{EXCHANGES}}` などの印は、同じように埋められます。

1. サーバーは、前の整理より後の依頼と返事を、最長72時間分渡します。最近更新された記録があれば、その場所も添えます。Claude Code は話題の1行と、`memory/` に覚えておく候補を返します。
2. サーバーは、結果を点検して、プロファイルごとの `state/self/tidy-days/` に日付別で保存します。`lacia self tidy YYYY-MM-DD` で読み返せます。`discord-log` が有効なときは、その日の日次ログにも「夜の整理」として書き足します。
3. 候補があれば窓口に知らせます。窓口は候補ごとに元の会話を確かめ、必要なことを `memory/` に書きます。

- 話題は1行で200字まで、候補は12件までで、1件は300字までです。整理するやり取りがある日は話題が必要です。
- 窓口がまだ受け取っていない候補はサーバーが持ち、次の夜のお知らせに添えます。
- 整理に失敗したときは、次の夜に処理していない分を再び渡します。日曜日には、1週間の話題と候補も渡します。
- 整理結果と「わたしのこと」は別々に点検し、保存します。書き直しに失敗しても、採用済みの整理結果は残ります。

## 分かっていないこと

- 自分についての記録が、返事や判断を実際にどう変えるかは、数週間の変わり方を、履歴で見て判断する必要があります。
- Claude Code のログインの期限が切れると、夜の記録に「採用しませんでした」と理由が出ます。期限が来る前に知らせる仕組みは、ありません。
