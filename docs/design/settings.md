# 設定の一覧

`lacia serve` の引数、記録のリポジトリーに置く設定、環境変数を調べられます。機能ごとの詳しい説明は、それぞれの節から開けます。

## 設定の書き方

形式1の記録のリポジトリーで `lacia serve` を起動すると、既定の設定では `127.0.0.1` だけで待ち受けます。手元のブラウザーで `http://127.0.0.1:10148/` を開いてください。依頼の受付、Git へのプッシュ、Discord への接続は、それぞれ設定すると使えます。

同じ設定が複数の場所にあるときは、次の順で優先します。

1. コマンドラインの引数（`--addr 0.0.0.0:8080` など）
2. `--config <ファイル>` で指定した設定ファイル
3. 記録のリポジトリーの `.lacia/serve.conf`（指定がなくても読みます。指定できる設定は、[限られています](#記録の側に置ける設定)）

ローカル環境で使い始めるときは、コマンドラインで `root`、`state`、`codex` か `claude` を指定できます。別の環境でサーバーを動かす場合も指定は同じです。毎回使う設定はファイルにまとめられます。 [ローカル環境で始める](../../README.md#ローカル環境で始める) · [別の環境で Web サーバーを動かす](../../README.md#別の環境で-web-サーバーを動かす)

設定ファイルには、1行に「名前 = 値」の形で書きます。名前は、引数の名前から先頭の `--` を除いたものです。空の行と、`#` で始まる行は、読み飛ばします。次は、同じ機械で2つのプロファイルを組にする例です。パスは、サーバーを動かす環境で使う絶対パスに置き換えます。

```
codex = codex

[work]
label = 仕事
url = http://127.0.0.1:10148
addr = 127.0.0.1:10148
root = /path/to/records-work
state = /path/to/state/example-work
peer = home

[home]
label = 家庭
url = http://127.0.0.1:10149
addr = 127.0.0.1:10149
root = /path/to/records-home
state = /path/to/state/example-home
pages = false
peer = work
inbox = true
```

- `[名前]` の行から下は、そのプロファイルだけの指定です。それより上は、どのプロファイルにも当てはまります。
- 起動のときに、`--profile <名前>` で、どのプロファイルとして動くかを選びます。1つのプロセスが動かすのは、1つのプロファイルです。別々の環境で組にする場合は、それぞれが相手を呼べるアドレスを `url` に書きます。 [複数のプロファイル](profiles.md)
- `config` と `profile` は、設定ファイルの中には書けません。
- 実行ファイルが知らない名前は、ログに書いて読み飛ばします。1つ前の実行ファイルへ戻したときにも、新しい設定ファイルのまま起動できるようにするためです。どの設定も、書かれていないことで受け付ける範囲が広がることはありません。

プロファイルの名前に、コードは意味を持たせていません。何をするかは、指定の組み合わせで決まります。

## `lacia serve` の設定

次の表は `lacia serve --help` に出る引数の一覧です。

### 基本

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| `config` | なし | 設定ファイルの場所です |
| `profile` | なし | 設定ファイルの中の、このプロセスが動かすプロファイルの名前です。`config` と一緒に使います |
| `addr` | `127.0.0.1:10148` | 待ち受けるアドレスです |
| `root` | 自動で探します | 記録のリポジトリーの場所です。指定を省くと、まず環境変数 `LACIA_TASKS` を使います。この変数もなければ、いまのディレクトリーから親を順にたどって探します |
| `state` | なし | 依頼の記録や、会話との接続の情報を置くディレクトリーです。記録のリポジトリーの外に置きます。依頼を受け付けるときは、必ず指定します |
| `rescan` | `10s` | ファイルの変更を取り込む間隔です。サーバーは同じ間隔で、タスクが待っている日時やほかのタスクの条件も確かめます |
| `site` | なし | このサーバーの公開のアドレスです。予定の連携の戻り先と、外からの呼び出しの見分けに使います（[複数のプロファイル](profiles.md#外から受け付ける入口)） |
| `pages` | `true` | `false` にすると、通常の画面と API を使えるのは、サーバーの手元からと、`site` に指定したアドレスからです。プロファイル間のやり取りと稼働確認には、別の入口があります |
| `git-sync` | `false` | 変更を Git へコミットして、プッシュします（[記録のリポジトリー](records.md#git-への保存)） |
| `user` | なし | サーバーが `LACIA_USER` に設定する、オーナーさんの呼び名です。省くと、環境変数 `LACIA_USER`、記録の `.lacia/config.json` の `user` の順に探し、どちらもなければ「オーナーさん」と呼びます |
| `label` | `通常モード` | このプロファイルの呼び名です。画面、「わたしのこと」の文書、相手のプロファイルへの伝言に出ます |
| `people` | `ほかの方` | オーナーさんのほかに話す方々を、レイシアがまとめて呼ぶときの名前です。たとえば `ご家族` と書きます。伝言、引き継ぎ、自分についての記録の依頼の文面に出ます |

### 依頼と会話

詳しい説明は、[依頼の受付](requests.md)にあります。

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| `codex` | なし | Codex を起動するコマンドです。指定すると、依頼を受け付けます |
| `codex-sandbox` | なし | Codex のサンドボックスの設定です（例：`danger-full-access`） |
| `codex-model` | Codex の設定のまま | Codex に使わせるモデルです。別のログインで起動する Codex（`lacia codex-login`）にも、同じモデルを渡します |
| `codex-effort` | Codex の設定のまま | Codex の推論の深さです（例：`medium`） |
| `claude` | なし | Claude Code を起動するコマンドです。`codex` と一緒にも指定できます |
| `window-rollover` | なし | 手が空いた窓口の会話を新しくする時間帯です。記録の `timezone`（既定は `Asia/Tokyo`）に合わせ、たとえば `05:00-12:00` と書きます。 [窓口の会話を決めた時間に切り替える](requests.md#窓口の会話を決めた時間に切り替える) |
| `default-kind` | Codex があれば `codex` | 種類を省いた依頼や予約をどちらへ渡すか選びます。使える値は `codex` と `claude` です |
| `places` | なし | 別の端末で動かす場所と、その端末の登録名、既定の種類、秘密ファイルを指定します（[実行先を選ぶ](schedules.md#実行先を選ぶ)） |
| `claude-model` | Claude Code の既定 | Claude Code に使わせるモデルです |
| `claude-permission` | `acceptEdits` | Claude Code の権限のモードです |
| `instructions` | なし | 会話への指示の文書です。指定すると、実行ファイルに入っている指示の代わりに使います |
| `instructions-extra` | なし | 会話への指示の最後に足す文書です。その環境だけに当てはまる決まりを書きます |
| `now` | `memory/now.md` | ふだんと違う状況を書いた文書の場所を、記録のリポジトリーからの相対パスで指定します。読み取れた内容を予約の依頼に添えます。[いまの状況を添える](schedules.md#いまの状況を添える) |
| `waits` | `true` | 会話の外で終わりを待つ仕組みを使います（[終了を待つ仕事](waits.md)） |

`codex` も `claude` もないサーバーは、画面とタスクの読み書きだけを行います。依頼、予約、自分についての記録、伝言、Discord は、依頼を受け付けるサーバーでだけ動きます。

### 予定

詳しい説明は、[予定の連携](calendar.md)にあります。

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| `calendars` | なし | 表示して読むカレンダーの一覧（JSON のファイル）です。指定がなければ、記録の `.lacia/calendars.json` を読みます。それもなければ、どのカレンダーも読みません |
| `google-client` | なし | Google Calendar を読むための OAuth クライアントの JSON です。指定がなく、`site` もないときは、実行ファイルに入っているクライアントを使います |
| `calendar-write` | `false` | 予定の連携で、読み取りに加えて、予定の作成や変更の許可も求めます。サーバーが自分から予定を書き換えることはありません |
| `calendar` | 下の説明 | 予定のスナップショットのファイルです |
| `calendar-overrides` | 記録の形式0では `personal/knowledge/calendar-display-overrides.json`、形式1では `.lacia/calendar-overrides.json` | 予定の表示の上書きを書いた JSON の、リポジトリーの中でのパスです。ファイルがなければ、上書きはしません |

`calendar` の指定がないときは、記録のリポジトリーの `calendar/snapshot.json`、`results/calendar-web-snapshot.md` の順に探します。`--state` を指定すると、配信する版は `<state>/calendar/snapshot.json` に保存します。`calendar` の指定と従来の場所は、以前の予約が作ったデータを取り込むときに使います。

### わたしのこと

詳しい説明は、[わたしのこと](self.md)にあります。

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| `self` | なし | 「わたしのこと」の文書の、リポジトリーの中でのパスです（例：`memory/self.md`）。指定すると、書き留めとページが使えます |
| `self-at` | なし | 自分についての記録を毎日書き直す時刻です。記録の `timezone`（既定は `Asia/Tokyo`）に合わせて `HH:MM` で指定します。指定がなければ、自動では書き直しません |
| `self-claude` | なし | 夜の整理と書き直しに使う Claude Code の実行ファイルです。引数は指定できません。実行ファイルを指定していないか、見つからない場合は、夜の処理を行いません |
| `self-model` | `fable` | 書き直すモデルです |
| `self-exchanges` | `true` | 夜の処理に最近の依頼と返事（最長72時間分）を含め、記録リポジトリーの参照を許可します。`false` のときも、前の版、書き留め、共有節の変更は書き直しの材料に残ります |
| `self-tidy` | `true` | 夜の書き直しに先立ち、話題と `memory/` に覚えておく候補を整理し、候補を窓口へ知らせます。`self-exchanges` が必要です。`discord-log` を設定した場合は、その日のログにも追記します |
| `self-improve` | `false` | 夜の書き直しで、「わたしのこと」の項目のうち、仕組みを直すほうがよさそうなものを候補に挙げ、窓口へ知らせます。タスクを持つプロファイルで有効にします。タスクを持たない記録では、設定しても動きません |
| `self-tidy-prompt` | なし | 夜の整理の指示文です。指定すると、実行ファイルに入っている指示文の代わりに使います。その環境に合う例を書きたいときに使います |
| `notice-log` | なし | 書き留めを日ごとに書き足すディレクトリーの、リポジトリーの中でのパスです（例：`log/notices`）。`discord-log` と同じにすると、やり取りと同じファイルに入ります |

### 複数のプロファイルと Discord

詳しい説明は、[複数のプロファイル](profiles.md)にあります。

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| `peer` | なし | 伝言と引き継ぎの相手にするプロファイルの名前です。相手の呼び名は、そのプロファイルの `label` から読みます。`config` と一緒に使います |
| `url` | なし | ほかのプロファイルがこのサーバーへの接続に使うアドレスです |
| `inbox` | `false` | 相手からの伝言を受けて、返事を返す側になります。`false` なら、伝言を送る側です |
| `discord` | `false` | Discord から依頼を受けます。接続先は、環境変数で指定します |
| `discord-members` | なし | Discord で受け付ける人の対応表（JSON のファイル）です。`discord` を使うときは、必ず指定します |
| `discord-log` | なし | Discord のやり取りを日ごとに書き足すディレクトリーの、リポジトリーの中でのパスです（例：`log/discord`） |
| `discord-log-entry` | `4000` | 日ごとのログに残す、1件の本文の上限（字）です |
| `discord-log-day` | `200000` | 1日分のログに本文を残す上限をバイト数で指定します。その発言を加えると上限を超える場合は、見出しと、本文を省いたことだけを書きます |

## 記録の側に置ける設定

記録のリポジトリーの `.lacia/serve.conf` で指定できるのは、次の13個です。

`label`、`google-client`、`calendar-write`、`calendar`、`calendars`、`calendar-overrides`、`now`、`self`、`self-at`、`self-model`、`self-exchanges`、`notice-log`、`instructions-extra`

ほかの名前は、ログに書いて読み飛ばします。理由は、[記録のリポジトリー](records.md#サーバーの設定のうち記録の側に置けるものlaciaserveconf)にあります。

`google-client`、`calendar`、`calendars`、`instructions-extra` に相対パスを書くと、記録のリポジトリーから数えます。`~/` は、ホームディレクトリーです。

## 記録の設定（`.lacia/config.json`）

| 項目 | 既定 | 中身 |
| --- | --- | --- |
| `format` | `0` | 記録の形式です。現在のタスク操作には形式1を使います |
| `areas` | `["work", "personal"]` | タスクを置く領域 |
| `area_labels` | なし | 領域の表示名 |
| `id_prefix` | `T` | 新しい ID の頭文字（英大文字1つ） |
| `user` | 「オーナーさん」 | オーナーさんの呼び名 |
| `reviewers` | なし | オーナーさんのほかに、確認を頼める人の名前 |
| `handoff_area` | 最初の領域 | 引き継がれたタスクを作る領域 |
| `calendar_hidden` | なし | 題名で表示から外す予定の規則（[予定の連携](calendar.md)） |
| `timezone` | `Asia/Tokyo` | 予約やタスクの日付、予定の取得と表示などに使う時間帯です。IANA の名前で指定します |

詳しい説明は、[記録のリポジトリー](records.md#記録の設定laciaconfigjson)にあります。

## 環境変数

| 名前 | 使う側 | 意味 |
| --- | --- | --- |
| `LACIA_TASKS` | コマンド | 記録のリポジトリーの場所 |
| `LACIA_API` | コマンド | 変更を頼むサーバーのアドレスです。サーバーが起動する会話には自動で渡ります。別の環境のサーバーを端末から使う場合は、その端末から届くアドレスを指定できます。`task list` と `task show` がサーバーから読む条件は、[読み取り専用のコピー](records.md#読み取り専用のコピー)にあります |
| `LACIA_USER` | コマンド、サーバー | オーナーさんの呼び名を指定します。記録の設定より優先します |
| `LACIA_BIN` | 会話 | `lacia` の実行ファイルの場所。`PATH` で見つからないときに使います |
| `LACIA_CONFIG_DIR` | `lacia codex`、`lacia claude`、`lacia agent` | このマシンの設定を置くディレクトリー。なければ `~/.config/lacia`（[ログインの一覧](logins.md#このマシンのログインの一覧)） |
| `LACIA_LOGIN` | コマンド | 会話を起動したログインの名前。`lacia` が、起動のときに渡す |
| `LACIA_ACTOR` | コマンド | 履歴に書く、書き込んだ人の名前 |
| `LACIA_PROFILE` | コマンド | 会話が動いている場所の名前です。サーバーのプロファイル名か、登録した端末の場所を使います。なければ `local` です。 [会話の名前と担当](waits.md#会話の名前と担当) |
| `LACIA_LOGINS` | `lacia codex-login` | ログインの設定のファイルの場所（[ログインの違う Codex を呼び分ける](logins.md)） |
| `LACIA_HANDOFF_API` | `lacia handoff` | 引き継ぎを送るサーバーのアドレス。なければ、設定の `peer` の相手へ送る |
| `DISCORD_BOT_TOKEN`、`DISCORD_BOT_TOKEN_FILE`、`DISCORD_GUILD_ID`、`DISCORD_CHANNEL_IDS` | サーバー | Discord の Bot の認証、接続先のサーバー、受付チャンネル |
| `DISCORD_MENTION_ALL_CHANNELS`、`DISCORD_MONITOR_ALL_CHANNELS` | サーバー | 受付チャンネル以外で、直接呼びかけられたときだけ応じるか、ほかの投稿も読んで返事の要否を判断するかを選べます。[Discord の設定](discord.md#ほかのチャンネルで呼びかける) |
